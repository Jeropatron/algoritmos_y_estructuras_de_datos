1 · Anatomía de la firma de un método

public static List<Integer> sinDuplicados(List<Integer> lista) {
    ...
}
  • public: se puede llamar desde afuera de la clase. Siempre en minúscula: Public no compila.
  • static: el método es de la clase, no de un objeto. Se llama CalisteniaListas.sinDuplicados(...), sin new. Es como una función suelta de Python. Sin static es un método de instancia, como los de tu Colecta.
  • List<Integer>, antes del nombre: el tipo de lo que devuelve. Si no devuelve nada, va void.
  • <Integer>: el genérico, o sea qué hay adentro de la lista. En colecciones va el wrapper (Integer, Double), nunca el primitivo (int, double).
  • (List<Integer> lista): los parámetros, cada uno con tipo y nombre.
  • Llaves y punto y coma: cada instrucción termina en ;. Las clases, los métodos y los if/for/while abren y cierran con { }. Si un método devuelve algo, todos los caminos tienen que terminar en return.

En tus páginas: clase_1_y_2 §1B.4 y §1B.12, y clase_5_y_6 §3.9.

3b · Atajos de la API: métodos que ya hacen el bucle por vos

Valen en el parcial («usando la API de List») y ahorran tiempo. Usalos cuando la operación es exactamente esa. Cuando la condición es propia (agrupar por persona, sumar si cumple algo), no hay atajo: va el bucle de §4.

4 · Recorrer una lista

// Con índice: cuando necesitás la posición
for (int i = 0; i < lista.size(); i++) {
    Integer x = lista.get(i);
}

// for-each: cuando solo necesitás cada elemento (Python: for x in lista)
for (Integer x : lista) {
    ...
}

// Armar una lista nueva mientras recorrés otra
List<Integer> resultado = new ArrayList<>();
for (Integer x : lista) {
    if (x > 0) {
        resultado.add(x);
    }
}
  • No agregues ni borres en la misma lista que estás recorriendo con for-each: tira ConcurrentModificationException. Para borrar según una condición: lista.removeIf(x -> x % 3 == 0);, o armá una lista nueva.

Ejemplo: los socios con 3 préstamos vencidos o más, ordenados por nombre.

public static List<Socio> morosos(List<Prestamo> prestamos) {
    List<Socio> resultado = new ArrayList<>();
    for (Socio socio : sociosDistintos(prestamos)) {          // 1) agrupar
        if (cantidadVencidos(prestamos, socio) >= 3) {        // 2) contar por socio y filtrar
            resultado.add(socio);
        }
    }
    resultado.sort((a, b) -> a.getNombre().compareTo(b.getNombre()));   // 3) ordenar
    return resultado;
}

private static List<Socio> sociosDistintos(List<Prestamo> prestamos) {
    List<Socio> socios = new ArrayList<>();
    for (Prestamo prestamo : prestamos) {
        if (!socios.contains(prestamo.getSocio())) {          // contains usa equals (§6)
            socios.add(prestamo.getSocio());
        }
    }
    return socios;
}

private static int cantidadVencidos(List<Prestamo> prestamos, Socio socio) {
    int cantidad = 0;
    for (Prestamo prestamo : prestamos) {
        if (prestamo.getSocio().equals(socio) && prestamo.estaVencido()) {
            cantidad++;
        }
    }
    return cantidad;
}
  • El método público se lee como la estrategia: agrupar, contar, filtrar, ordenar. Cada auxiliar hace una sola cosa.
  • Los auxiliares son private: no forman parte de lo que te pidieron.
  • Sigue habiendo un recorrido adentro de otro, pero en métodos distintos. Para la complejidad cuenta igual (ver §14).

Los puntos del checklist que más puntos cuestan, en un TDA chico (una Playlist sobre arreglo). Cada comentario dice qué punto cumple.

public enum EstadoPlaylist {                   // estados: enum, no booleans (punto 11)
    EN_EDICION, PUBLICADA
}

public class Playlist {
    private final Cancion[] canciones;         // private (4) · final: el arreglo no se reemplaza
    private int cantidad;
    private EstadoPlaylist estado;

    /**
     * Crea una playlist vacía, en edición.
     * pre: capacidad > 0.
     * post: cantidad = 0 y estado = EN_EDICION.
     * @param capacidad la cantidad máxima de canciones
     * @throws IllegalArgumentException si capacidad <= 0
     */
    public Playlist(int capacidad) {           // la capacidad entra por parámetro: nada de new Cancion[100] (8 y 9)
        if (capacidad <= 0) {
            throw new IllegalArgumentException("La capacidad debe ser positiva: " + capacidad);
        }
        this.canciones = new Cancion[capacidad];
        this.cantidad = 0;
        this.estado = EstadoPlaylist.EN_EDICION;
    }

    /**
     * pre: cancion no es null, la playlist está en edición y no está llena.
     * post: cancion queda al final y cantidad aumenta en 1.
     * @throws IllegalArgumentException si cancion es null
     * @throws IllegalStateException si la playlist está publicada o llena
     */
    public void agregar(Cancion cancion) {     // recibe el objeto entero, no sus atributos sueltos (16)
        if (cancion == null) {
            throw new IllegalArgumentException("La canción no puede ser null");
        }
        if (estado != EstadoPlaylist.EN_EDICION) {     // un enum se compara con ==
            throw new IllegalStateException("La playlist ya está publicada");
        }
        if (cantidad == canciones.length) {
            throw new IllegalStateException("La playlist está llena");
        }
        canciones[cantidad] = cancion;
        cantidad++;
    }

    /** post: la suma de las duraciones, calculada en el momento. */
    public int duracionTotal() {               // lo calculable es un método, no un atributo (15)
        int total = 0;
        for (int i = 0; i < cantidad; i++) {
            total += canciones[i].getDuracion();
        }
        return total;
    }

    /** post: la duración promedio, o null si no hay canciones. */
    public Double duracionPromedio() {         // Double, no double: así puede devolver null (10)
        if (cantidad == 0) {
            return null;
        }
        return (double) duracionTotal() / cantidad;    // el casteo va antes de dividir
    }

    /** post: una copia de las canciones cargadas; modificarla no cambia la playlist. */
    public Cancion[] getCanciones() {
        return Arrays.copyOf(canciones, cantidad);     // copia defensiva (18)
    }
}
  • «No hay valor» va con el wrapper: un método que devuelve double o int no puede devolver null. Si «no hay» es una respuesta posible, el tipo de retorno es Double, Integer o un objeto (Cancion).
  • Qué excepción usar: IllegalArgumentException cuando el problema es un parámetro. IllegalStateException cuando el parámetro está bien, pero el objeto no está en un estado que lo permita (publicada, llena). Si no querés pensar en eso, IllegalArgumentException para todo también se acepta.
  • Si el arreglo tiene que crecer (§9), no puede ser final: teclas = Arrays.copyOf(...) lo reemplaza.
  • Nada de System.out.println adentro del TDA (17): los mensajes van en la excepción y la impresión la hace el main.

11 · Herencia, clases abstractas e interfaces (solo si el TDA las pide)

Ningún enunciado las exigió, pero el profe las usó en su solución del Televisor. Si modelás «tipos de» algo, esta es la sintaxis:

public interface Encendible {                  // contrato puro: solo firmas
    void encender();
}

public abstract class Electrodomestico {       // abstract: no se puede hacer new Electrodomestico(...)
    private final String marca;

    protected Electrodomestico(String marca) {
        this.marca = marca;
    }

    public abstract int consumo();             // sin cuerpo: cada hija lo implementa

    public String getMarca() {
        return marca;
    }
}

public class Televisor extends Electrodomestico implements Encendible {
    private final int pulgadas;
    private boolean encendido;

    public Televisor(String marca, int pulgadas) {
        super(marca);                          // primera línea: el constructor de la madre
        this.pulgadas = pulgadas;
    }

    @Override
    public int consumo() {
        return pulgadas * 2;
    }

    @Override
    public void encender() {
        encendido = true;
    }
}

Electrodomestico e = new Televisor("X", 40);   // polimorfismo
e.consumo();                                   // 80: ejecuta el de Televisor
  • extends una sola clase; implements todas las interfaces que quieras, separadas por coma.
  • Lo private de la madre no se ve en la hija: se usa su getter (getMarca()).
  • @Override hace que el compilador chequee que la firma coincide. Si te equivocás en el nombre, no compila (sin @Override, creás un método nuevo sin darte cuenta).

13 · Recursión en Java (U6)

En el parcial, lo esperable es que la U6 entre como pregunta conceptual o V/F. Si te piden escribir algo recursivo, estos tres moldes alcanzan:

// Molde 1: el problema se achica de a uno
public static int factorial(int n) {
    if (n <= 1) {                      // caso base: se responde sin llamarse
        return 1;
    }
    return n * factorial(n - 1);       // paso recursivo: el mismo problema, más chico
}
// T(n) = T(n−1) + O(1) → O(n) de tiempo y O(n) de pila

// Molde 2: recorrer una lista con un índice. El público delega en un privado con un parámetro más
public static int sumar(List<Integer> numeros) {
    return sumarDesde(numeros, 0);
}

private static int sumarDesde(List<Integer> numeros, int desde) {
    if (desde == numeros.size()) {     // caso base: no quedan elementos
        return 0;
    }
    return numeros.get(desde) + sumarDesde(numeros, desde + 1);
}

// Molde 3: dividir a la mitad (búsqueda binaria en un arreglo ordenado)
private static boolean contiene(int[] a, int x, int desde, int hasta) {   // busca en a[desde, hasta)
    if (desde >= hasta) {              // caso base: rango vacío
        return false;
    }
    int medio = (desde + hasta) / 2;
    if (a[medio] == x) {
        return true;
    }
    if (x < a[medio]) {
        return contiene(a, x, desde, medio);
    }
    return contiene(a, x, medio + 1, hasta);
}
// T(n) = T(n/2) + O(1) → O(log n)
  • Primero el caso base, después el paso recursivo. Sin caso base (o si nunca se alcanza) da StackOverflowError.
  • Achicá con índices, no con copias: new ArrayList<>(lista.subList(1, n)) en cada llamada cuesta O(n) por llamada y el total se vuelve O(n²).
  • Java no optimiza la recursión de cola: para recorrer listas largas, un for es más seguro.

En tus páginas: U6 §6.2.2 Caso base y paso recursivo, §6.2.3 La pila de llamadas, §6.5.1 Búsqueda binaria y «Cómo lo pregunta el profe» (después de §6.12).

/**
 * Complejidad: O(n²), con n = lista.size().
 * El for da n vueltas y en cada una contains recorre el resultado,
 * que tiene hasta n elementos: n · n.
 * Con new ArrayList<>(new LinkedHashSet<>(lista)) bajaría a O(n).
 */
  • Decí qué es n. Si hay dos tamaños (dos listas), usá n y m, y no los mezcles.
  • Un método auxiliar llamado adentro de un for cuesta lo mismo que si su for estuviera escrito ahí: se multiplica.
  • Lo que va uno después del otro se suma y queda el mayor; lo de adentro de un bucle se multiplica por las vueltas.

U4

Complejidad de tu método

  • Lo que va uno después del otro se SUMA (queda el mayor); lo que va adentro de un bucle se MULTIPLICA por las vueltas.
  • contains, indexOf y remove(objeto) en una lista son O(n): adentro de un for que da n vueltas, el total es O(n²).
  • Ordenar (sort) es O(n log n). get(i) en un ArrayList es O(1); en una lista enlazada, O(n).
  • Al final, descartá constantes y términos menores: O(2n + 10) es O(n).
  • En una recurrencia, primero mirá si resta (T(n−1): sustracción) o divide (T(n/2): división). Con resta y a > 1, es exponencial.
