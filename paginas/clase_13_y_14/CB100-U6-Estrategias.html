Unidad 6

Estrategias: recursividad, división y conquista y ordenamientos no comparativos
Objetivos de la unidad

Al terminar esta unidad vas a poder: (1) escribir un algoritmo recursivo identificando su caso base y su paso recursivo; (2) seguir la ejecución en la pila de llamadas; (3) reconocer cuándo una recursión explota y cómo arreglarla; (4) explicar los tres pasos de la división y conquista y aplicarlos a búsqueda binaria, Mergesort, Quicksort, Hanói y Karatsuba; (5) plantear la recurrencia de cada uno y resolverla con el Teorema Maestro de la Unidad 4; (6) explicar por qué ningún ordenamiento por comparación baja de n log n y cómo Counting, Radix y Bucket sort esquivan ese límite.

Hasta ahora resolvimos casi todo con bucles: recorrer, acumular, buscar. Esta unidad presenta dos formas distintas de pensar un problema. La primera es la recursividad: definir la solución en términos de una versión más chica del mismo problema. La segunda, que se apoya en la primera, es la división y conquista: partir el problema en pedazos, resolver cada uno y combinar. Al final vemos un tercer truco, ordenar sin comparar, que rompe un límite que parecía imposible de superar.

6.1Un poco de historia

La recursión es una idea vieja de la matemática: las definiciones recursivas de Peano, por ejemplo. En algoritmos, John von Neumann describió Mergesort en 1945; entre 1959 y 1961, Tony Hoare inventó Quicksort; y en 1960 Anatoli Karatsuba multiplicó dos números en menos de O(n²), refutando una conjetura de Kolmogorov que decía que no se podía. En 1969, Volker Strassen hizo lo mismo con la multiplicación de matrices. Todas estas ideas mostraron que partir un problema y recombinarlo puede cambiar radicalmente su costo.

6.2Recursividad

6.2.1La idea: un problema que contiene una versión más chica de sí mismo

Pensá en la suma 1 + 2 + … + n. Se puede ver como un bucle que acumula, pero también así: la suma hasta n es n más la suma hasta n − 1. Y la suma hasta n − 1 es n − 1 más la suma hasta n − 2… hasta llegar a algo que sabés sin calcular: la suma hasta 0 es 0.

static int suma(int n) {
    if (n == 0) {
        return 0;                 // lo que sé sin calcular
    }
    return n + suma(n - 1);       // la versión más chica del mismo problema
}

Eso es la recursividad: un método que, para resolver su problema, se llama a sí mismo sobre una entrada más chica. Lo raro al principio es que el método se usa antes de terminar de escribirlo. El truco mental es el salto de fe: cuando escribís suma(n - 1), no intentes seguir todas las llamadas en tu cabeza. Confiá en que esa llamada devuelve la suma correcta hasta n − 1, y preguntate solo cómo usás ese resultado para armar el tuyo.

Si venís de Python o de C

La recursión funciona igual en los tres lenguajes: un método o función que se llama a sí mismo. Lo único propio de Java es que cada llamada ocupa un marco en el stack, el mismo que estudiaste en la Unidad 2, y que la JVM no optimiza la recursión de cola (sección 6.2.4).

6.2.2Caso base y paso recursivo

Todo algoritmo recursivo tiene dos partes, y las dos son obligatorias:

Caso base

Una entrada tan simple que se resuelve sin volver a llamarse. Es lo que corta la cadena de llamadas: sin caso base, la recursión no termina nunca.

Paso recursivo

Reduce el problema a una versión más chica del mismo problema, se llama sobre ella y usa ese resultado para armar el propio. Sin paso recursivo, no es recursión.

Estos son los tres ejemplos de la clase (material/i06_estrategias/RecursividadBasica.java). Cada uno tiene en el comentario su ecuación de recurrencia, que es la herramienta de la Unidad 4 para calcular su costo:

/** n! = n · (n−1)!  ·  T(n) = T(n−1) + O(1) → O(n). Caso base: 0! = 1. */
public static long factorial(int n) {
    if (n < 0) {
        throw new IllegalArgumentException("n negativo");
    }
    if (n <= 1) {
        return 1;                                   // caso base
    }
    return n * factorial(n - 1);                    // paso recursivo
}

/** Suma de a[desde..n−1]  ·  T(n) = T(n−1) + O(1) → O(n). */
public static long sumar(int[] a, int desde) {
    if (desde == a.length) {
        return 0;                                   // caso base: nada que sumar
    }
    return a[desde] + sumar(a, desde + 1);          // paso recursivo
}

/** base^exp  ·  T(exp) = T(exp−1) + O(1) → O(exp). */
public static long potencia(long base, int exp) {
    if (exp == 0) {
        return 1;                                   // caso base
    }
    return base * potencia(base, exp - 1);          // paso recursivo
}

Fijate en sumar: para recorrer un arreglo de forma recursiva se agrega un parámetro, el índice desde, que avanza en cada llamada. Es el patrón de casi todos los ejercicios fáciles de la guía. El arreglo no se achica: lo que se achica es la parte que falta recorrer.

Tres preguntas para escribir cualquier recursión:

  1. ¿Cuál es la entrada más chica que sé resolver sin recursión? Ese es el caso base.
  2. ¿Cómo achico el problema? Restándole uno, partiéndolo a la mitad o avanzando un índice.
  3. Si confío en que la llamada sobre el problema chico devuelve lo correcto, ¿cómo armo mi respuesta con ese resultado?
Los tres errores que hacen que una recursión no termine
  • Falta el caso base. El método se llama para siempre.
  • El problema no se achica: por ejemplo return n * factorial(n);, con n en vez de n - 1.
  • El caso base es inalcanzable para algunas entradas. Si el caso base es n == 0 y alguien llama con n = -1, el problema baja a −2, −3… y nunca llega a 0. Por eso factorial valida n < 0 y usa n <= 1.

En los tres casos el resultado es el mismo: un StackOverflowError (sección 6.2.3).

6.2.3La pila de llamadas: cómo se ejecuta una recursión

Ya conocés el stack de la Unidad 2: cada vez que se llama un método, la JVM apila un marco con sus parámetros, sus variables locales y el lugar adonde volver cuando termine. La recursión no tiene nada especial: cada llamada recursiva es una llamada más y apila su propio marco, con su propia copia de n.

La ejecución tiene dos fases. A la ida, las llamadas se apilan hasta llegar al caso base. A la vuelta, cada marco recibe el resultado de la llamada de abajo, hace su cuenta, devuelve y se desapila:

Dos consecuencias que se preguntan:

  • La recursión usa memoria aunque no cree objetos. Cada marco ocupa lugar en el stack. Una recursión de profundidad n usa O(n) de memoria de pila, mientras que el bucle equivalente usa O(1).
  • Si la recursión no termina, el stack se llena. Los marcos se apilan hasta agotar el espacio reservado y la JVM lanza StackOverflowError. No es una Exception común: es un Error, y no se atrapa con catch (Exception e).

6.2.4Recursión vs. iteración

Todo lo que se hace con recursión se puede hacer con un bucle, y viceversa. Para el factorial:

static long factorialIterativo(int n) {
    long resultado = 1;
    for (int i = 2; i <= n; i++) {
        resultado *= i;
    }
    return resultado;
}

La complejidad temporal es la misma, O(n), pero la memoria no: el bucle usa una sola variable. Y Java tiene una particularidad: la JVM no optimiza la recursión de cola. Otros lenguajes, cuando la llamada recursiva es lo último que hace el método, la convierten en un bucle y no apilan marcos nuevos. Java no: cada llamada ocupa su marco igual. Por eso una recursión muy profunda, como recorrer un millón de elementos de a uno, termina en StackOverflowError.

RecursiónIteración
Memoria extraO(profundidad), un marco por llamadaO(1) en general
Límite prácticomiles de llamadas anidadas, después StackOverflowErrorsin límite de profundidad
Brilla enproblemas que se dividen (Mergesort, Hanói, árboles)recorridos lineales (sumar, buscar, contar)

Regla práctica: si el problema se parte en pedazos (división y conquista, árboles), la recursión es natural y su profundidad es chica, del orden de log n. Si el problema es lineal y la entrada puede ser grande, preferí el bucle.

6.3Tipos de recursividad

No todas las recursiones tienen la misma forma. El apunte las clasifica en cuatro tipos según dos preguntas: ¿cuántas llamadas hace cada activación? y ¿quién llama a quién? Cada tipo tiene su propia silueta en la pila y su propio costo.

TipoDefiniciónEjemplo
Lineal (o simple)Cada activación hace una sola llamada recursiva. La pila es una fila de marcos.factorial, suma, búsqueda binaria
MúltipleCada activación hace dos o más llamadas. Las llamadas forman un árbol.Fibonacci, caminosEnGrilla, Mergesort, Hanói
Indirecta (o mutua)A llama a B y B vuelve a llamar a A: el ciclo pasa por dos o más métodos.esPar / esImpar
AnidadaEl argumento de la llamada recursiva es otra llamada recursiva: f(f(...)).función 91 de McCarthy

Múltiple: el árbol. ¿De cuántas formas se puede ir de la esquina superior izquierda a la inferior derecha de una grilla, moviéndose solo hacia la derecha o hacia abajo? A cada casilla se llega desde arriba o desde la izquierda, así que los caminos se suman, con una llamada por cada opción:

public static long caminosEnGrilla(int filas, int columnas) {
    if (filas == 1 || columnas == 1) {
        return 1;                                   // caso base: en un pasillo hay un solo camino
    }
    return caminosEnGrilla(filas - 1, columnas)     // vengo desde arriba
         + caminosEnGrilla(filas, columnas - 1);    // o desde la izquierda
}

caminosEnGrilla(3, 3) devuelve 6. Con a llamadas por activación y n niveles, el árbol puede tener hasta an nodos: es el Teorema Maestro por sustracción con a > 1. La múltiple es la base de la división y conquista, con una diferencia crucial. Si las llamadas trabajan sobre mitades distintas (Mergesort), el árbol suma O(n log n). Si trabajan sobre casi lo mismo (Fibonacci, esta grilla), los subproblemas se repiten y el árbol explota.

Indirecta: el ciclo pasa por dos métodos. Ninguno de los dos se llama a sí mismo, pero esPar llama a esImpar y viceversa. La idea: n es par si n − 1 es impar, hasta bajar al 0, que es par:

public static boolean esPar(int n) {
    if (n == 0) {
        return true;                    // caso base: el 0 es par
    }
    return esImpar(n - 1);              // n es par si n-1 es impar
}

public static boolean esImpar(int n) {
    if (n == 0) {
        return false;                   // caso base: el 0 no es impar
    }
    return esPar(n - 1);                // n es impar si n-1 es par
}

esPar(4) llama a esImpar(3), que llama a esPar(2)… hasta esPar(0), que devuelve true. En la pila se alternan los dos métodos. El ciclo A → B → A no se ve mirando un solo método: hay que leerlos juntos. Y el caso base puede estar en cualquiera de los dos, pero tiene que existir y ser alcanzable. (Es el ejercicio e08 de la guía; en la práctica, la paridad es n % 2 == 0.)

Anidada: la llamada adentro de la llamada. El ejemplo célebre es la función 91 de McCarthy (1970):

public static int mcCarthy91(int n) {
    if (n > 100) {
        return n - 10;                          // caso base
    }
    return mcCarthy91(mcCarthy91(n + 11));      // la llamada DENTRO de la llamada
}

Primero se resuelve la llamada interna, porque es la que decide el argumento de la externa. Con n = 99: la interna es mcCarthy91(110), que da 100, y recién entonces corre la externa, mcCarthy91(100), que vuelve a anidar… hasta devolver 91. Lo sorprendente es que devuelve 91 para todo n ≤ 100. La anidada más famosa es la función de Ackermann, que crece tan rápido que se usa para demostrar límites teóricos de la recursión.

Idea clave

Para clasificar una recursión, hacete dos preguntas. ¿Cuántas llamadas hace cada activación? Una: lineal; varias: múltiple. ¿Quién llama a quién? A sí mismo: directa; a otro que lo vuelve a llamar: indirecta; con la llamada como argumento de otra: anidada. Y la pregunta de rendimiento de siempre: ¿los subproblemas son distintos o se repiten?

6.4Cuidado con los subproblemas repetidos: Fibonacci

La definición de Fibonacci es recursiva: fib(0) = 0, fib(1) = 1 y fib(n) = fib(n−1) + fib(n−2). Escrita tal cual en Java:

static long fib(int n) {
    if (n <= 1) {
        return n;                          // casos base: fib(0) = 0, fib(1) = 1
    }
    return fib(n - 1) + fib(n - 2);        // DOS llamadas recursivas
}

Es correcta, pero para n = 50 no termina en un tiempo razonable. El problema es que recalcula los mismos subproblemas una y otra vez:

Cada llamada abre dos más, así que el árbol se duplica por nivel. Su recurrencia es T(n) = T(n−1) + T(n−2) + O(1), que crece como O(2n). Es el mismo fenómeno del Teorema Maestro por sustracción con a > 1 (Unidad 4, §4.8): restar achica el problema muy de a poco y, si además se ramifica, explota.

La solución es no repetir trabajo. Hay dos formas:

// 1) Memoización: guardar cada fib(k) ya calculado. O(n) tiempo y memoria.
static long fibMemo(int n, long[] memo) {
    if (n <= 1) {
        return n;
    }
    if (memo[n] != 0) {
        return memo[n];                    // ya lo calculé: no recalculo
    }
    memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
    return memo[n];
}

// 2) Iterativa de abajo hacia arriba: O(n) tiempo y O(1) memoria.
static long fibIterativo(int n) {
    long anterior = 0, actual = 1;
    for (int i = 0; i < n; i++) {
        long siguiente = anterior + actual;
        anterior = actual;
        actual = siguiente;
    }
    return anterior;
}

La memoización es la semilla de una estrategia que vas a ver más adelante en la materia, la programación dinámica. El Laboratorio 2 cuenta las llamadas de las tres versiones.

6.5División y conquista

La división y conquista (en inglés divide and conquer, también llamada «divide y vencerás») es una forma de usar la recursión para problemas grandes. Tiene siempre tres pasos:

1 · Dividir

Partir el problema en dos o más subproblemas del mismo tipo, más chicos. Por ejemplo, las dos mitades de un arreglo.

2 · Conquistar

Resolver cada subproblema recursivamente, hasta llegar a un caso base tan chico que se resuelve directo.

3 · Combinar

Juntar las soluciones parciales para armar la del problema original. Por ejemplo, fusionar dos mitades ordenadas.

El costo se describe con la recurrencia de la Unidad 4:

T(n) = a · T(n/b) + f(n)

Acá a es la cantidad de subproblemas, n/b el tamaño de cada uno y f(n) el costo de dividir y combinar. Se resuelve con el Teorema Maestro por división (Unidad 4, §4.9).

¿Restar o dividir?

No toda recursión es división y conquista. El factorial y la suma restan uno: T(n) = T(n−1) + O(1), que se resuelve con el Teorema Maestro por sustracción. La división y conquista divide: T(n/2). La diferencia es enorme. Restar da un árbol de n niveles; dividir, uno de log n. Antes de aplicar cualquier Teorema Maestro, mirá el argumento de T: ¿resta o divide?

6.5.1Búsqueda binaria: dividir y descartar

Es la división y conquista más simple. En un arreglo ordenado se mira el elemento del medio. Si es el buscado, listo. Si no, el orden te dice en qué mitad no puede estar, y se descarta entera:

/** Busca x en a[ini..fin] (a ordenado). Devuelve la posición o -1. */
static int buscar(int[] a, int x, int ini, int fin) {
    if (ini > fin) {
        return -1;                                  // caso base: rango vacío, no está
    }
    int medio = (ini + fin) / 2;
    if (a[medio] == x) {
        return medio;                               // caso base: encontrado
    }
    if (x < a[medio]) {
        return buscar(a, x, ini, medio - 1);        // conquistar SOLO la izquierda
    }
    return buscar(a, x, medio + 1, fin);            // o SOLO la derecha
}

Hay una sola llamada recursiva sobre la mitad, y el trabajo fuera de ella es constante: T(n) = T(n/2) + O(1). Con el Teorema Maestro: a = 1, b = 2, nlog₂ 1 = n0 = 1, que empata con f(n) = 1. Es el caso 2: Θ(log n). Para un millón de elementos son unas 20 comparaciones. El requisito es que el arreglo esté ordenado; si no lo está, el descarte no tiene sentido.

6.6Mergesort

Mergesort (ordenamiento por mezcla) ordena así: divide el arreglo por la mitad, ordena cada mitad recursivamente y fusiona las dos mitades ordenadas en una sola. Todo el trabajo inteligente está en combinar:

/** Ordena a[ini..fin), fin excluido. */
static void mergesort(int[] a, int ini, int fin) {
    if (fin - ini <= 1) {
        return;                                 // caso base: 0 o 1 elemento ya está ordenado
    }
    int medio = (ini + fin) / 2;
    mergesort(a, ini, medio);                   // conquistar la mitad izquierda
    mergesort(a, medio, fin);                   // conquistar la mitad derecha
    fusionar(a, ini, medio, fin);               // combinar: O(n)
}

/** Fusiona a[ini..medio) y a[medio..fin), ya ordenadas, en una sola ordenada. */
static void fusionar(int[] a, int ini, int medio, int fin) {
    int[] aux = new int[fin - ini];
    int i = ini, j = medio, k = 0;
    while (i < medio && j < fin) {
        if (a[i] <= a[j]) {                      // <= y no <: así es estable
            aux[k++] = a[i++];
        } else {
            aux[k++] = a[j++];
        }
    }
    while (i < medio) aux[k++] = a[i++];       // lo que sobró de la izquierda
    while (j < fin)   aux[k++] = a[j++];       // lo que sobró de la derecha
    System.arraycopy(aux, 0, a, ini, aux.length);
}

6.6.1La clave: fusionar dos mitades ordenadas

Todo el trabajo de Mergesort está en la fusión. Se pone un puntero al principio de cada mitad, se comparan los dos elementos apuntados, se copia el menor a la salida y se avanza solo ese puntero. Cuando una mitad se agota, se copia de un tirón lo que queda de la otra, que ya está ordenado. Fusionando [3, 27, 38] con [9, 10, 82] (el ejemplo del apunte):

6.6.2Complejidad y propiedades

La recurrencia: dos llamadas sobre la mitad más una fusión lineal, T(n) = 2T(n/2) + O(n). Con el Teorema Maestro: nlog₂ 2 = n, que empata con f(n) = n. Es el caso 2: Θ(n log n).

Por qué es O(n log n) siempre, en el mejor, el promedio y el peor caso: la división es siempre por la mitad y la fusión siempre cuesta lineal, sin importar cómo vengan los datos. No hay una entrada «mala» que desbalancee el árbol. A cambio, la fusión necesita un arreglo auxiliar: O(n) de memoria extra. Y es estable: dos elementos iguales conservan su orden original, gracias al <= de la fusión.

6.7Quicksort

Quicksort también es división y conquista, pero reparte el trabajo al revés. Elige un pivote y particiona el arreglo: los menores a la izquierda, los mayores a la derecha y el pivote en su lugar definitivo. Después ordena cada lado. Como cada parte ya quedó en su zona, combinar no cuesta nada:

/** Ordena a[ini..fin], fin incluido. */
static void quicksort(int[] a, int ini, int fin) {
    if (ini >= fin) {
        return;                                 // caso base: 0 o 1 elemento
    }
    int p = particionar(a, ini, fin);           // dividir: el pivote queda en p
    quicksort(a, ini, p - 1);                   // conquistar los menores
    quicksort(a, p + 1, fin);                   // conquistar los mayores
}                                               // combinar: nada que hacer

/** Partición de Lomuto: el último elemento es el pivote. */
static int particionar(int[] a, int ini, int fin) {
    int pivote = a[fin];
    int i = ini;                                // a[ini..i) son los menores
    for (int j = ini; j < fin; j++) {
        if (a[j] < pivote) {
            int t = a[i]; a[i] = a[j]; a[j] = t;
            i++;
        }
    }
    int t = a[i]; a[i] = a[fin]; a[fin] = t;    // el pivote, a su lugar
    return i;
}

6.7.1¿Por qué el peor caso es O(n²)?

El riesgo está en el pivote. Si en promedio parte el arreglo en dos mitades, queda T(n) = 2T(n/2) + O(n), o sea O(n log n). Pero si el pivote es siempre el menor o el mayor, parte en 0 y n−1. En vez de dividir, resta uno: T(n) = T(n−1) + O(n), que da O(n²). Con la partición de Lomuto eso pasa justo con el arreglo ya ordenado. En la práctica se evita eligiendo el pivote con criterio, al azar o como la mediana de tres (el primero, el del medio y el último), lo que hace el peor caso extremadamente improbable.

6.8Multiplicación rápida: Karatsuba

Multiplicar dos números de n dígitos «a mano», como en la escuela, cuesta O(n²). En 1960, Anatoli Karatsuba mostró que con división y conquista se puede menos.

Se parte cada número en dos mitades: x = a·10m + b e y = c·10m + d. Entonces:

x · y = ac · 102m + (ad + bc) · 10m + bd

Así planteado pide cuatro multiplicaciones de la mitad de tamaño: ac, ad, bc y bd. El truco es obtener el término del medio con una sola multiplicación extra:

ad + bc = (a + b)(c + d) − ac − bd

Como ac y bd ya están calculados, alcanza con calcular (a+b)(c+d) y restar. Quedan tres multiplicaciones más sumas y corrimientos, que son lineales.

Ejemplo chico: 12 × 34, con m = 1. Las mitades son a = 1, b = 2, c = 3 y d = 4.

  • ac = 3, bd = 8 y (a+b)(c+d) = 3 · 7 = 21.
  • El término del medio es ad + bc = 21 − 3 − 8 = 10.
  • El resultado es 3 · 100 + 10 · 10 + 8 = 408, que es efectivamente 12 × 34.

El ejemplo del apunte: 34 × 56, con a = 3, b = 4, c = 5 y d = 6. Las tres multiplicaciones son ac = 15, bd = 24 y (a+b)(c+d) = 7 · 11 = 77. El término del medio es 77 − 15 − 24 = 38 (comprobalo: ad + bc = 18 + 20 = 38, sin haberlas multiplicado). El resultado es 15 · 100 + 38 · 10 + 24 = 1904.

La recurrencia baja de 4T(n/2) a T(n) = 3T(n/2) + O(n). Con el Teorema Maestro: nlog₂ 3 ≈ n1,585 crece más que f(n) = n, así que es el caso 1: O(n1,585), mejor que O(n²). Para n = 1000 dígitos son unas 60.000 operaciones contra el millón del método escolar. Con la misma idea, Strassen multiplica matrices con 7 multiplicaciones de bloques en vez de 8: O(n2,807) en lugar de O(n³). La lección general: en división y conquista, ahorrarse una sola llamada recursiva cambia el orden de complejidad.

El código de la clase está en material/i06_estrategias/Karatsuba.java. Usa BigInteger y parte en potencias de 2 en vez de 10, pero la idea es la misma.

6.9Ordenar sin comparar

El límite de comparar: por qué no se baja de n log n.

Mergesort, Quicksort, Heapsort, Bubble sort… todos ordenan comparando pares de elementos: «¿es a < b?». Y hay un resultado sorprendente: ningún algoritmo que ordene solo comparando puede hacer menos de del orden de n log n comparaciones en el peor caso. No es que todavía no se haya encontrado uno mejor: es imposible.

El argumento: cada comparación tiene dos resultados posibles y lleva el algoritmo por una rama u otra. Todo el algoritmo es un árbol de decisión binario.

  • Para ordenar n elementos, el algoritmo tiene que poder distinguir entre sus n! órdenes posibles, así que el árbol necesita al menos n! hojas.
  • Un árbol binario con n! hojas tiene altura de al menos log₂(n!), y esa altura es la cantidad de comparaciones del peor caso.
  • Por la aproximación de Stirling, log₂(n!) = Θ(n log n).

Con 3 elementos hay 3! = 6 órdenes posibles, y log₂ 6 ≈ 2,6: ningún algoritmo comparativo ordena 3 elementos con 2 comparaciones en todos los casos.

¿Cómo se esquiva? No comparando. Si las claves son enteros de un rango acotado, se puede usar el valor mismo como índice de un arreglo. Así trabajan los tres ordenamientos no comparativos que siguen, y por eso pueden ser lineales.

6.9.1Counting sort

Counting sort (ordenamiento por conteo) ordena enteros de un rango acotado [0, k] en dos pasadas:

  1. Contar: recorre el arreglo y, en un arreglo auxiliar conteo indexado por el valor, suma uno por cada aparición.
  2. Reconstruir: recorre conteo de 0 a k y escribe cada valor tantas veces como se contó.
public static int[] ordenar(int[] a, int maximo) {
    int[] conteo = new int[maximo + 1];
    for (int x : a) {
        conteo[x]++;                        // contar apariciones: el VALOR es el índice
    }
    int[] resultado = new int[a.length];
    int i = 0;
    for (int valor = 0; valor <= maximo; valor++) {
        while (conteo[valor]-- > 0) {
            resultado[i++] = valor;         // reconstruir en orden
        }
    }
    return resultado;
}

Ejemplo con {4, 2, 2, 8, 3, 3, 1} y máximo 8:

valor012345678
conteo012210001

Al reconstruir sale [1, 2, 2, 3, 3, 4, 8]. Nunca se comparó un elemento con otro.

Costo: O(n + k): n para contar y reconstruir, más k para recorrer el rango. Si k es del orden de n, es lineal. Deja de convenir cuando el rango es mucho más grande que la cantidad de elementos, como ordenar 10 números que van de 0 a mil millones: el O(k) domina y además gasta memoria proporcional a k. Y no sirve para objetos que solo se pueden comparar, sin una clave entera acotada.

6.9.2Radix sort

¿Y si el rango es grande, como números de hasta 6 dígitos? Radix sort (ordenamiento por dígitos) ordena dígito por dígito, del menos significativo al más significativo (versión LSD). En cada pasada usa un counting sort estable con solo 10 valores posibles, del 0 al 9.

Ejemplo con {170, 45, 75, 90, 2, 802, 24, 66}:

1unidades170 90 2 802 24 45 75 66
2decenas2 802 24 45 66 170 75 90

Por qué tiene que ser estable: en la pasada 3, el 24 y el 45 tienen el mismo dígito de centenas (0). Si el ordenamiento por dígito fuera inestable, podría invertirlos y perder el orden que dejaron las pasadas anteriores. La estabilidad garantiza que, ante un empate en el dígito actual, manda el orden de los dígitos menos significativos, que ya quedó resuelto.

Costo: O(d · (n + b)), con d dígitos y base b (10). Para números de tamaño acotado, d y b son constantes y queda prácticamente O(n). 6.9.3Bucket sort

Bucket sort (ordenamiento por cubetas o baldes) sirve para números reales uniformemente distribuidos, por ejemplo en [0, 1):

  1. Crea n cubetas vacías, cada una para un subrango: la 0 para [0; 0,1), la 1 para [0,1; 0,2), y así.
  2. Reparte cada valor en su cubeta: la de x es la ⌊n · x⌋.
  3. Ordena cada cubeta por separado. Como son chicas, cualquier método sirve.
  4. Concatena las cubetas en orden.

Ejemplo con 10 valores: 0,78 va a la cubeta 7; 0,17 y 0,12, a la 1; 0,26, 0,21 y 0,23, a la 2… Se ordena cada cubeta (la 2 queda 0,21 0,23 0,26) y al concatenar sale la lista ordenada.

El ejemplo del apunte, paso a paso, con {0.42, 0.26, 0.72, 0.17, 0.68, 0.09}: n = 6, así que hay 6 cubetas y cada una cubre un subrango de ancho 1/6.

Se ordenan por dentro las cubetas 1 ([0,26; 0,17] → [0,17; 0,26]) y 4 ([0,72; 0,68] → [0,68; 0,72]), y al concatenar de la 0 a la 5 sale 0,09 0,17 0,26 0,42 0,68 0,72. Queda ordenado por dos garantías: entre cubetas, todo lo de la cubeta i es menor que lo de la i + 1; y dentro de cada cubeta, el paso 2 ya ordenó. El código del apunte, con una lista de listas porque no se sabe de antemano cuántos valores recibe cada cubeta:

public static double[] ordenar(double[] a) {
    int n = a.length;
    List<List<Double>> baldes = new ArrayList<>();      // Paso 1: n cubetas vacías
    for (int i = 0; i < n; i++) {
        baldes.add(new ArrayList<>());
    }
    for (double x : a) {
        int indice = (int) (n * x);                     // la cubeta de x es ⌊n·x⌋
        baldes.get(indice).add(x);
    }
    for (List<Double> balde : baldes) {                // Paso 2: ordenar cada una
        Collections.sort(balde);
    }
    double[] resultado = new double[n];                 // Paso 3: concatenar en orden
    int k = 0;
    for (List<Double> balde : baldes) {
        for (double x : balde) {
            resultado[k++] = x;
        }
    }
    return resultado;
}

Costo: si los datos están bien repartidos, cada cubeta tiene en promedio un elemento y el total es O(n) en promedio. Si no lo están, el peor caso es que todo caiga en la misma cubeta: entonces cuesta lo que cueste ordenar esa cubeta, O(n²) con un método simple. La garantía depende de la distribución de los datos, no del algoritmo.

6.10Ejemplo integrador: las Torres de Hanói

Hay tres varillas (A, B y C) y n discos de distinto tamaño apilados en A, el más grande abajo. Hay que pasarlos todos a C con dos reglas: se mueve un disco por vez y nunca un disco grande arriba de uno chico.

Pensarlo con bucles es un lío. Con recursión es tres líneas, usando el salto de fe: «supongamos que ya sé mover n−1 discos».

  1. Muevo los n−1 discos de arriba de A a B, usando C de auxiliar.
  2. Muevo el disco más grande de A a C. Ahora está libre.
  3. Muevo los n−1 discos de B a C, usando A de auxiliar.
/** Imprime los movimientos para pasar n discos de origen a destino. */
public static void resolver(int n, char origen, char destino, char auxiliar) {
    if (n == 0) {
        return;                                          // caso base: nada que mover
    }
    resolver(n - 1, origen, auxiliar, destino);          // 1) n−1 al auxiliar
    System.out.println("mover disco " + n + " de " + origen + " a " + destino);
    resolver(n - 1, auxiliar, destino, origen);          // 3) n−1 al destino
}

/** Cantidad de movimientos: 2ⁿ − 1. */
public static long movimientos(int n) {
    if (n == 0) {
        return 0;
    }
    return 2 * movimientos(n - 1) + 1;
}

La recurrencia: dos llamadas sobre n−1 más un movimiento, T(n) = 2T(n−1) + 1. Es sustracción con a = 2 > 1, o sea exponencial: exactamente 2n − 1 movimientos. Con 3 discos son 7; con 20, más de un millón; con 64 (la leyenda), más de 18 trillones. No hay forma más rápida: el problema mismo exige esa cantidad. Lo probás en el Laboratorio 4.

6.11Errores comunes

Error común
  • Olvidar el caso base, o escribir uno que no se alcanza para algunas entradas, como los negativos: termina en StackOverflowError.
  • No achicar el problema en la llamada recursiva: f(n) en vez de f(n - 1).
  • Intentar seguir todas las llamadas en la cabeza en vez de confiar en la llamada recursiva (el salto de fe).
  • Creer que la recursión no usa memoria: cada llamada apila un marco, así que la profundidad n cuesta O(n) de stack.
  • Usar Fibonacci recursivo ingenuo sin notar que es exponencial: recalcula subproblemas.
  • Aplicar el Teorema Maestro por división a una recurrencia que resta, como Hanói o el factorial.
  • Decir que Quicksort es O(n log n) sin aclarar: ese es el promedio; el peor caso es O(n²).
  • Creer que Counting sort siempre es lineal: es O(n + k), y con un rango k enorme no conviene.
  • En Radix, usar un ordenamiento por dígito que no sea estable: se pierde el orden de las pasadas anteriores.

«¿Cómo es la estrategia de ordenamiento del método Radix?»

Radix es un ordenamiento no comparativo para enteros (o claves de largo fijo). Ordena dígito por dígito, del menos significativo al más significativo, y en cada pasada usa un ordenamiento estable (counting sort sobre 10 valores). La estabilidad hace que, al ordenar por un dígito, los empates conserven el orden logrado con los dígitos anteriores. «Describa la estrategia de diseño de algoritmos Divide y Vencerás»

Es una estrategia recursiva con tres pasos: dividir el problema en subproblemas más chicos del mismo tipo, conquistar resolviendo cada uno recursivamente hasta un caso base trivial, y combinar las soluciones parciales. Su costo se expresa como T(n) = a·T(n/b) + f(n) (a subproblemas de tamaño n/b, f(n) el costo de dividir y combinar) y se resuelve con el Teorema Maestro. Ejemplos: búsqueda binaria O(log n), Mergesort O(n log n), Karatsuba O(n1,585).

Las diez teóricas de la guía (guia/i06_estrategias/i01_teorico), con su respuesta. Intentá responderlas por escrito antes de abrir la respuesta: es el formato de las preguntas para desarrollar del coloquio.

1¿Qué dos partes tiene todo algoritmo recursivo y para qué sirve cada una?

Todo algoritmo recursivo tiene un caso base y un paso recursivo. El caso base es una entrada tan simple que se resuelve sin volver a llamarse, y es lo que corta la cadena de llamadas para que la recursión termine. El paso recursivo reduce el problema a una versión más chica del mismo problema y se llama a sí mismo sobre ella, confiando en que esa llamada resolverá el subproblema. Sin caso base la recursión no termina; sin paso recursivo no es recursión.

2¿Qué es la pila de llamadas y qué error se produce si la recursión no termina?

La pila de llamadas (call stack) es la estructura donde la JVM guarda, apilada, cada llamada a método que está en curso: sus parámetros, sus variables locales y a dónde volver cuando termine. Cada llamada recursiva apila un nuevo marco; cuando una llamada retorna, su marco se desapila. Si la recursión no termina (falta el caso base o el problema no se achica), los marcos se apilan sin fin hasta agotar el espacio reservado para la pila, y se lanza un StackOverflowError.

3¿La JVM optimiza la recursión de cola (tail call)? ¿Qué implica esto para recursiones muy profundas?

No. A diferencia de otros lenguajes (varios funcionales, o compiladores con tail call optimization), la JVM no convierte automáticamente una recursión de cola en un bucle, así que cada llamada sigue ocupando un marco en la pila aunque sea lo último que hace el método. En consecuencia, una recursión muy profunda (por ejemplo, recorrer linealmente millones de elementos recursivamente) puede desbordar la pila y lanzar StackOverflowError. Cuando la profundidad puede ser grande, conviene reescribir el algoritmo de forma iterativa (con un bucle y, si hace falta, una pila explícita).

4¿Por qué el Fibonacci recursivo ingenuo es O(2n)? ¿Cómo se lo mejora a O(n)?

Porque recalcula los mismos subproblemas una y otra vez. fib(n) llama a fib(n-1) y fib(n-2), que a su vez vuelven a pedir fib(n-2), fib(n-3), etc.; el árbol de llamadas se ramifica en dos en cada nivel y su tamaño crece exponencialmente. Su recurrencia T(n) = T(n-1) + T(n-2) + O(1) da del orden de O(2n). Se lo mejora no repitiendo trabajo: con memoización (guardar en una tabla cada fib(k) ya calculado) o, mejor, con una versión iterativa bottom-up que arranca de fib(0) y fib(1) y va sumando hacia arriba, guardando sólo los dos últimos valores. Ambas resuelven en O(n) (la iterativa, además, en O(1) de memoria).

5Enumerá y explicá los tres pasos de la división y conquista.
  1. Dividir: partir el problema en dos o más subproblemas más chicos del mismo tipo que el original (por ejemplo, las dos mitades de un arreglo).
  2. Resolver (conquistar): resolver cada subproblema recursivamente, hasta llegar a un caso base tan chico que se resuelve directo.
  3. Combinar: unir las soluciones parciales para armar la solución del problema original (por ejemplo, fusionar dos mitades ordenadas en una sola ordenada).

El costo total se describe con una recurrencia T(n) = a T(n/b) + f(n), donde a es la cantidad de subproblemas, n/b su tamaño y f(n) el costo de dividir y combinar; se resuelve con el Teorema Maestro.

6Planteá la recurrencia de Mergesort y resolvela con el Teorema Maestro. ¿Por qué es O(n log n) siempre?

Mergesort divide el arreglo en dos mitades (a = 2 subproblemas de tamaño n/2, o sea b = 2) y luego fusiona las dos mitades ordenadas recorriéndolas en paralelo, lo que cuesta f(n) = O(n). La recurrencia es:

T(n) = 2 T(n/2) + O(n)

Comparando f(n) = n con nlogb a = nlog2 2 = n1 = n, estamos en el Caso 2 del Teorema Maestro (f(n) = Θ(nlogb a)), que da T(n) = Θ(n log n). Es O(n log n) siempre (mejor, promedio y peor caso) porque la división es siempre en dos mitades iguales y la fusión siempre cuesta lineal, sin depender del orden previo de los datos: no hay un "peor caso" que degrade la partición como sí ocurre en Quicksort.

7¿En qué se diferencian Mergesort y Quicksort? Indicá el peor caso y el uso de memoria de cada uno.

Ambos son división y conquista, pero reparten el trabajo distinto. Mergesort hace la parte difícil al combinar: divide siempre por la mitad (trivial) y el trabajo está en la fusión de dos mitades ordenadas. Quicksort hace la parte difícil al dividir: elige un pivote y particiona en menores y mayores (ahí está el trabajo), y la combinación es trivial porque las partes ya quedan en su lugar.

Diferencias clave:

  • Peor caso. Mergesort: O(n log n) garantizado. Quicksort: O(n2) (cuando el pivote cae siempre en un extremo y la partición queda muy desbalanceada), aunque en promedio es O(n log n).
  • Memoria. Mergesort necesita O(n) de memoria extra para fusionar. Quicksort ordena in place, con sólo O(log n) de pila en promedio.
  • Estabilidad. Mergesort es estable; Quicksort, en su forma habitual, no.

En la práctica Quicksort suele ser el más rápido por sus constantes chicas y por no usar memoria extra, pese a su peor caso teórico peor.

8¿Cómo logra Karatsuba multiplicar con tres multiplicaciones en vez de cuatro? ¿Qué complejidad alcanza?

Al multiplicar dos números partidos en mitades, x = a· 2m + b e y = c· 2m + d, el producto es

xy = ac· 22m + (ad + bc)· 2m + bd

Directamente eso pide cuatro multiplicaciones de tamaño mitad: ac, ad, bc y bd. El truco de Karatsuba es notar que el término del medio ad + bc se puede obtener con una sola multiplicación extra en vez de dos, usando la identidad:

ad + bc = (a+b)(c+d) - ac - bd

Como ac y bd ya los calculamos, alcanza con computar (a+b)(c+d) y restar. Quedan tres multiplicaciones (ac, bd y (a+b)(c+d)) más algunas sumas y corrimientos, que son lineales. La recurrencia baja de 4 T(n/2) a T(n) = 3 T(n/2) + O(n), que por el Teorema Maestro (Caso 1) da O(nlog2 3) ≈ O(n1.585), mejor que el O(n2) escolar.

9¿Por qué ningún ordenamiento por comparación puede bajar de O(n log n) en el peor caso?

Porque un algoritmo que sólo puede comparar pares de elementos (preguntar "¿es a < b?") está, en esencia, recorriendo un árbol de decisión binario: cada comparación tiene dos resultados posibles y lleva a una rama distinta. Para ordenar n elementos hay que poder distinguir entre sus n! ordenamientos posibles, así que el árbol necesita al menos n! hojas. Un árbol binario con n! hojas tiene altura mínima log2(n!), y por la aproximación de Stirling log2(n!) = Θ(n log n). Esa altura es la cantidad de comparaciones en el peor caso: por lo tanto, cualquier algoritmo basado en comparaciones necesita al menos del orden de n log n comparaciones. Los ordenamientos no comparativos (Counting, Radix, Bucket) esquivan este límite porque no comparan: usan el valor de las claves como índice, y por eso pueden ser lineales.

10Explicá Counting sort. ¿Cuál es su costo y en qué caso deja de convenir?

Counting sort ordena enteros de un rango acotado [0, k] sin comparar. Primero recorre el arreglo y cuenta cuántas veces aparece cada valor, guardando los conteos en un arreglo auxiliar indexado por el valor. Después recorre ese arreglo de conteos en orden y reconstruye la salida, escribiendo cada valor tantas veces como se contó. Como usa el valor como índice, nunca compara elementos entre sí.

Su costo es O(n + k): O(n) para contar y reconstruir, más O(k) para recorrer el rango. Si k es del orden de n (rango chico), es efectivamente lineal y más rápido que el O(n log n) de los comparativos. Deja de convenir cuando el rango k es mucho más grande que n (por ejemplo, ordenar diez números que van de 0 a mil millones): ahí el término O(k) domina y además gasta memoria proporcional a k. Tampoco sirve para objetos que sólo se pueden comparar (no numéricos / sin clave entera acotada).

     * Auxiliar recursivo que busca dentro del rango cerrado [lo, hi].
     *
     * @param a  arreglo ordenado
     * @param x  valor buscado
     * @param lo limite inferior del rango (inclusive)
     * @param hi limite superior del rango (inclusive)
     * @return indice de {@code x} o {@code -1}
     */
    private static int buscar(int[] a, int x, int lo, int hi) {
        if (lo > hi) {
            return -1; // caso base: rango vacio, no esta
        }
        int medio = lo + (hi - lo) / 2; // evita desborde de (lo + hi)
        if (a[medio] == x) {
            return medio; // caso base: lo encontramos
        }
        if (x < a[medio]) {
            return buscar(a, x, lo, medio - 1); // buscamos en la mitad izquierda
        }
        return buscar(a, x, medio + 1, hi); // buscamos en la mitad derecha
    }

    public static void main(String[] args) {
        int[] datos = {1, 3, 5, 7, 9, 11, 13};
        System.out.println("Buscar 7  -> indice " + buscar(datos, 7));
        System.out.println("Buscar 1  -> indice " + buscar(datos, 1));
        System.out.println("Buscar 13 -> indice " + buscar(datos, 13));
        System.out.println("Buscar 8  -> indice " + buscar(datos, 8));
    }
}

Mergesort

Ordenamiento por mezcla (Mergesort), un algoritmo de división y conquista.

Pista

Idea:

  • Dividir: partir el arreglo por la mitad.
  • Conquistar: ordenar recursivamente cada mitad.
  • Combinar: fusionar las dos mitades ya ordenadas.

Complejidad: O(n log n) en todos los casos. Es estable.

import java.util.Arrays;

/**
 * e02: ordenamiento por mezcla (Mergesort), un algoritmo de division y conquista.
 *
 * <p>Idea:</p>
 * <ul>
 *   <li><b>Dividir:</b> partir el arreglo por la mitad.</li>
 *   <li><b>Conquistar:</b> ordenar recursivamente cada mitad.</li>
 *   <li><b>Combinar:</b> fusionar las dos mitades ya ordenadas.</li>
 * </ul>
 *
 * <p>Complejidad: O(n log n) en todos los casos. Es estable.</p>
 */
public final class Mergesort {

    private Mergesort() {
    }

    /**
     * Devuelve un nuevo arreglo con los elementos de {@code a} ordenados de forma
     * ascendente. El arreglo original no se modifica.
     *
     * @param a arreglo a ordenar (no se modifica)
     * @return nuevo arreglo ordenado
     */
    public static int[] ordenar(int[] a) {
        int[] copia = Arrays.copyOf(a, a.length);
        if (copia.length > 1) {
            ordenar(copia, 0, copia.length - 1);
        }
        return copia;
    }

    /** Ordena in-place el rango cerrado [lo, hi] de {@code a}. */
    private static void ordenar(int[] a, int lo, int hi) {
        if (lo >= hi) {
            return; // caso base: 0 o 1 elemento ya esta ordenado
        }
        int medio = lo + (hi - lo) / 2;
        ordenar(a, lo, medio);        // ordenar mitad izquierda
        ordenar(a, medio + 1, hi);    // ordenar mitad derecha
        fusionar(a, lo, medio, hi);   // combinar ambas mitades
    }

    /** Fusiona los rangos ordenados [lo, medio] y [medio+1, hi]. */
    private static void fusionar(int[] a, int lo, int medio, int hi) {
        int[] izq = Arrays.copyOfRange(a, lo, medio + 1);
        int[] der = Arrays.copyOfRange(a, medio + 1, hi + 1);
        int i = 0;
        int j = 0;
        int k = lo;
        while (i < izq.length && j < der.length) {
            if (izq[i] <= der[j]) { // <= mantiene la estabilidad
                a[k++] = izq[i++];
            } else {
                a[k++] = der[j++];
            }
        }
        while (i < izq.length) {
            a[k++] = izq[i++];
        }
        while (j < der.length) {
            a[k++] = der[j++];
        }
    }

    public static void main(String[] args) {
        int[] datos = {5, 2, 9, 1, 5, 6, 3};
        System.out.println("Original: " + Arrays.toString(datos));
        System.out.println("Ordenado: " + Arrays.toString(ordenar(datos)));
    }
}

Quicksort

Ordenamiento rápido (Quicksort), un algoritmo de división y conquista.

Pista

Idea:

  • Dividir: elegir un pivote y particionar el arreglo dejando a la izquierda los menores y a la derecha los mayores.
  • Conquistar: ordenar recursivamente cada partición.
  • Combinar: no hace falta, la partición ya deja todo en su lugar.

Complejidad: O(n log n) en promedio, O(n^2) en el peor caso. Trabaja in-place sobre una copia para no alterar el arreglo original.

import java.util.Arrays;

/**
 * e03: ordenamiento rapido (Quicksort), un algoritmo de division y conquista.
 *
 * <p>Idea:</p>
 * <ul>
 *   <li><b>Dividir:</b> elegir un pivote y particionar el arreglo dejando a la
 *       izquierda los menores y a la derecha los mayores.</li>
 *   <li><b>Conquistar:</b> ordenar recursivamente cada particion.</li>
 *   <li><b>Combinar:</b> no hace falta, la particion ya deja todo en su lugar.</li>
 * </ul>
 *
 * <p>Complejidad: O(n log n) en promedio, O(n^2) en el peor caso. Trabaja
 * in-place sobre una copia para no alterar el arreglo original.</p>
 */
public final class Quicksort {

    private Quicksort() {
    }

    /**
     * Devuelve un nuevo arreglo con los elementos de {@code a} ordenados de forma
     * ascendente. El arreglo original no se modifica.
     *
     * @param a arreglo a ordenar (no se modifica)
     * @return nuevo arreglo ordenado
     */
    public static int[] ordenar(int[] a) {
        int[] copia = Arrays.copyOf(a, a.length);
        ordenar(copia, 0, copia.length - 1);
        return copia;
    }

    /** Ordena in-place el rango cerrado [lo, hi]. */
    private static void ordenar(int[] a, int lo, int hi) {
        if (lo >= hi) {
            return; // caso base: 0 o 1 elemento
        }
        int p = particionar(a, lo, hi);
        ordenar(a, lo, p - 1);  // ordenar los menores al pivote
        ordenar(a, p + 1, hi);  // ordenar los mayores al pivote
    }

    /**
     * Particion de Lomuto usando {@code a[hi]} como pivote. Deja el pivote en su
     * posicion final y devuelve ese indice.
     */
    private static int particionar(int[] a, int lo, int hi) {
        int pivote = a[hi];
        int i = lo - 1; // indice del ultimo elemento menor al pivote
        for (int j = lo; j < hi; j++) {
            if (a[j] <= pivote) {
                i++;
                intercambiar(a, i, j);
            }
        }
        intercambiar(a, i + 1, hi); // ubicamos el pivote
        return i + 1;
    }

    private static void intercambiar(int[] a, int i, int j) {
        int tmp = a[i];
        a[i] = a[j];
        a[j] = tmp;
    }

    public static void main(String[] args) {
        int[] datos = {5, 2, 9, 1, 5, 6, 3};
        System.out.println("Original: " + Arrays.toString(datos));
        System.out.println("Ordenado: " + Arrays.toString(ordenar(datos)));
    }
}

Potencia rápida

Exponenciacion rápida (por cuadrados), un algoritmo de división y conquista.

Pista

Idea: en lugar de multiplicar base por si misma exp veces (O(exp)), se usa la identidad:

  • si exp es par: base^exp = (base^(exp/2))^2
  • si exp es impar: base^exp = base * base^(exp-1)

Cada paso reduce el exponente a la mitad, por lo que la complejidad es O(log exp).

/**
 * e04: exponenciacion rapida (por cuadrados), un algoritmo de division y conquista.
 *
 * <p>Idea: en lugar de multiplicar {@code base} por si misma {@code exp} veces
 * (O(exp)), se usa la identidad:</p>
 * <ul>
 *   <li>si {@code exp} es par: {@code base^exp = (base^(exp/2))^2}</li>
 *   <li>si {@code exp} es impar: {@code base^exp = base * base^(exp-1)}</li>
 * </ul>
 *
 * <p>Cada paso reduce el exponente a la mitad, por lo que la complejidad es
 * O(log exp).</p>
 */
public final class PotenciaRapida {

    private PotenciaRapida() {
    }

    /**
     * Calcula {@code base} elevado a {@code exp} en O(log exp).
     *
     * @param base base de la potencia
     * @param exp  exponente no negativo
     * @return {@code base^exp}
     * @throws IllegalArgumentException si {@code exp} es negativo
     */
    public static long potencia(long base, int exp) {
        if (exp < 0) {
            throw new IllegalArgumentException("el exponente no puede ser negativo: " + exp);
        }
        if (exp == 0) {
            return 1L; // caso base: cualquier base^0 = 1
        }
        long mitad = potencia(base, exp / 2); // resolvemos un subproblema de tamano mitad
        long cuadrado = mitad * mitad;
        if (exp % 2 == 0) {
            return cuadrado;          // exponente par
        }
        return base * cuadrado;       // exponente impar
    }

    public static void main(String[] args) {
        System.out.println("2^0  = " + potencia(2, 0));
        System.out.println("2^10 = " + potencia(2, 10));
        System.out.println("3^5  = " + potencia(3, 5));
        System.out.println("2^62 = " + potencia(2, 62));
    }
}

Mínimo y máximo a la vez

Mínimo y máximo simultaneos con división y conquista.

Pista

Se parte el arreglo por la mitad, se obtiene el (min, max) de cada mitad y se combinan quedándose con el menor de los mínimos y el mayor de los máximos.

La complejidad sigue siendo O(n), pero este enfoque hace aproximadamente 3n/2 comparaciones, menos que las 2n de un recorrido ingenuo.

import java.util.Arrays;

/**
 * e05: minimo y maximo simultaneos con division y conquista.
 *
 * <p>Se parte el arreglo por la mitad, se obtiene el (min, max) de cada mitad y
 * se combinan quedandose con el menor de los minimos y el mayor de los maximos.</p>
 *
 * <p>La complejidad sigue siendo O(n), pero este enfoque hace aproximadamente
 * {@code 3n/2} comparaciones, menos que las {@code 2n} de un recorrido ingenuo.</p>
 */
public final class MinMax {

    private MinMax() {
    }

    /**
     * Devuelve el minimo y el maximo del arreglo.
     *
     * @param a arreglo no vacio
     * @return arreglo de dos posiciones {@code {min, max}}
     * @throws IllegalArgumentException si {@code a} es vacio
     */
    public static int[] minMax(int[] a) {
        if (a.length == 0) {
            throw new IllegalArgumentException("el arreglo no puede ser vacio");
        }
        return minMax(a, 0, a.length - 1);
    }

    /** Devuelve {min, max} del rango cerrado [lo, hi]. */
    private static int[] minMax(int[] a, int lo, int hi) {
        if (lo == hi) {
            return new int[]{a[lo], a[lo]}; // caso base: un solo elemento
        }
        if (hi - lo == 1) { // caso base: dos elementos, una comparacion
            if (a[lo] <= a[hi]) {
                return new int[]{a[lo], a[hi]};
            }
            return new int[]{a[hi], a[lo]};
        }
        int medio = lo + (hi - lo) / 2;
        int[] izq = minMax(a, lo, medio);
        int[] der = minMax(a, medio + 1, hi);
        int min = Math.min(izq[0], der[0]);
        int max = Math.max(izq[1], der[1]);
        return new int[]{min, max};
    }

    public static void main(String[] args) {
        int[] datos = {5, 2, 9, 1, 5, 6, 3};
        int[] r = minMax(datos);
        System.out.println("Datos: " + Arrays.toString(datos));
        System.out.println("min = " + r[0] + ", max = " + r[1]);
    }
}

Fibonacci en O(n)

Números de Fibonacci de forma eficiente en O(n).

Pista

La definición natural fib(n) = fib(n-1) + fib(n-2) calculada de forma recursiva pura es exponencial (O(2^n)) porque recalcula los mismos subproblemas una y otra vez. Aca usamos un enfoque iterativo bottom-up que guarda solo los dos ultimos valores, logrando O(n) tiempo y O(1) memoria.

Definición:

  • fib(0) = 0
  • fib(1) = 1
  • fib(n) = fib(n-1) + fib(n-2) para n >= 2
/**
 * e06: numeros de Fibonacci de forma eficiente en O(n).
 *
 * <p>La definicion natural {@code fib(n) = fib(n-1) + fib(n-2)} calculada de
 * forma recursiva pura es exponencial (O(2^n)) porque recalcula los mismos
 * subproblemas una y otra vez. Aca usamos un enfoque iterativo bottom-up que
 * guarda solo los dos ultimos valores, logrando O(n) tiempo y O(1) memoria.</p>
 *
 * <p>Definicion:</p>
 * <ul>
 *   <li>fib(0) = 0</li>
 *   <li>fib(1) = 1</li>
 *   <li>fib(n) = fib(n-1) + fib(n-2) para n &gt;= 2</li>
 * </ul>
 */
public final class Fibonacci {

    private Fibonacci() {
    }

    /**
     * Calcula el n-esimo numero de Fibonacci en O(n).
     *
     * @param n indice no negativo
     * @return el valor de {@code fib(n)}
     * @throws IllegalArgumentException si {@code n} es negativo
     */
    public static long fib(int n) {
        if (n < 0) {
            throw new IllegalArgumentException("n no puede ser negativo: " + n);
        }
        if (n < 2) {
            return n; // casos base: fib(0)=0, fib(1)=1
        }
        long anterior = 0L; // fib(0)
        long actual = 1L;   // fib(1)
        for (int i = 2; i <= n; i++) {
            long siguiente = anterior + actual;
            anterior = actual;
            actual = siguiente;
        }
        return actual;
    }

    public static void main(String[] args) {
        for (int i = 0; i <= 10; i++) {
            System.out.print(fib(i) + " ");
        }
        System.out.println();
        System.out.println("fib(50) = " + fib(50));
    }
}

Torres de Hanói

Torres de Hanoi, un clasico ejemplo de recursividad.

Pista

Para mover n discos desde la varilla origen a la destino usando una varilla auxiliar:

  1. Mover los n-1 discos de arriba de origen a auxiliar (subproblema).

  3. Mover los n-1 discos de auxiliar a destino (subproblema).

La cantidad de movimientos es exactamente 2^n - 1.

/**

 *   <li>Mover los {@code n-1} discos de auxiliar a destino (subproblema).</li>

    }

     * Devuelve la lista ordenada de movimientos para resolver el juego con

     *

     * @return lista de movimientos, cada uno como "mover disco X de A a C"

    public static List<String> resolver(int n) {

    private static void resolver(int n, char origen, char destino, char auxiliar,

Contar inversiones

Conteo de inversiones con una variante de Mergesort en O(n log n).

Pista

Una inversion es un par de indices (i, j) con i < j y a[i] > a[j]: mide que tan lejos esta el arreglo de estar ordenado. Un arreglo ordenado tiene 0 inversiones; uno ordenado al reves tiene el máximo n(n-1)/2.

La idea es que durante la fusion de Mergesort, cada vez que tomamos un elemento de la mitad derecha antes que uno de la izquierda, ese elemento forma una inversion con todos los que quedan pendientes en la mitad izquierda.

import java.util.Arrays;

/**
 * e08: conteo de inversiones con una variante de Mergesort en O(n log n).
 *
 * <p>Una inversion es un par de indices {@code (i, j)} con {@code i < j} y
 * {@code a[i] > a[j]}: mide que tan lejos esta el arreglo de estar ordenado.
 * Un arreglo ordenado tiene 0 inversiones; uno ordenado al reves tiene el maximo
 * {@code n(n-1)/2}.</p>
 *
 * <p>La idea es que durante la fusion de Mergesort, cada vez que tomamos un
 * elemento de la mitad derecha antes que uno de la izquierda, ese elemento forma
 * una inversion con todos los que quedan pendientes en la mitad izquierda.</p>
 */
public final class ContarInversiones {

    private ContarInversiones() {
    }

    /**
     * Cuenta la cantidad de inversiones de {@code a} sin modificar el original.
     *
     * @param a arreglo de entrada (no se modifica)
     * @return cantidad de pares {@code (i, j)} con {@code i < j} y {@code a[i] > a[j]}
     */
    public static long contar(int[] a) {
        int[] copia = Arrays.copyOf(a, a.length);
        return ordenarYContar(copia, 0, copia.length - 1);
    }

    /** Ordena in-place [lo, hi] y devuelve las inversiones halladas en ese rango. */
    private static long ordenarYContar(int[] a, int lo, int hi) {
        if (lo >= hi) {
            return 0L; // caso base: 0 o 1 elemento, sin inversiones
        }
        int medio = lo + (hi - lo) / 2;
        long total = ordenarYContar(a, lo, medio);
        total += ordenarYContar(a, medio + 1, hi);
        total += fusionarYContar(a, lo, medio, hi);
        return total;
    }

    /** Fusiona [lo, medio] y [medio+1, hi] contando las inversiones cruzadas. */
    private static long fusionarYContar(int[] a, int lo, int medio, int hi) {
        int[] izq = Arrays.copyOfRange(a, lo, medio + 1);
        int[] der = Arrays.copyOfRange(a, medio + 1, hi + 1);
        int i = 0;
        int j = 0;
        int k = lo;
        long inversiones = 0L;
        while (i < izq.length && j < der.length) {
            if (izq[i] <= der[j]) {
                a[k++] = izq[i++];
            } else {
                // izq[i] > der[j]: der[j] es menor que izq[i] y que todos los
                // elementos restantes de la mitad izquierda.
                a[k++] = der[j++];
                inversiones += izq.length - i;
            }
        }
        while (i < izq.length) {
            a[k++] = izq[i++];
        }
        while (j < der.length) {
            a[k++] = der[j++];
        }
        return inversiones;
    }

    public static void main(String[] args) {
        int[] datos = {2, 4, 1, 3, 5};
        System.out.println("Datos: " + Arrays.toString(datos));
        System.out.println("Inversiones: " + contar(datos));
    }
}

    }

    /** Maxima suma contigua dentro del rango cerrado [lo, hi]. */
    private static int sumaMaxima(int[] a, int lo, int hi) {
        if (lo == hi) {
            return a[lo]; // caso base: un solo elemento
        }
        int medio = lo + (hi - lo) / 2;
        int maxIzq = sumaMaxima(a, lo, medio);
        int maxDer = sumaMaxima(a, medio + 1, hi);
        int maxCruce = maxCruzando(a, lo, medio, hi);
        return Math.max(maxCruce, Math.max(maxIzq, maxDer));
    }

    /**
     * Maxima suma de un subarreglo que cruza el medio, es decir que usa {@code a[medio]}
     * y {@code a[medio+1]}. Se extiende hacia la izquierda y hacia la derecha
     * tomando el mejor prefijo/sufijo desde el centro.
     */
    private static int maxCruzando(int[] a, int lo, int medio, int hi) {
        int sumaIzq = Integer.MIN_VALUE;
        int acum = 0;
        for (int i = medio; i >= lo; i--) {
            acum += a[i];
            sumaIzq = Math.max(sumaIzq, acum);
        }
        int sumaDer = Integer.MIN_VALUE;
        acum = 0;
        for (int j = medio + 1; j <= hi; j++) {
            acum += a[j];
            sumaDer = Math.max(sumaDer, acum);
        }
        return sumaIzq + sumaDer;
    }

    public static void main(String[] args) {
        int[] datos = {-2, 1, -3, 4, -1, 2, 1, -5, 4};
        System.out.println("Suma maxima: " + sumaMaxima(datos)); // 6 -> {4,-1,2,1}
    }
}

Karatsuba con long

Multiplicación de enteros con la idea de Karatsuba.

Pista

La multiplicación escolar de dos números de n dígitos hace O(n^2) productos de un dígito. Karatsuba parte cada número en dos mitades y, mediante un truco algebraico, resuelve el problema con tres multiplicaciones de la mitad del tamano en vez de cuatro, bajando la complejidad a O(n^1.585).

Si x = x1 * 10^m + x0 e y = y1 * 10^m + y0, entonces:

  z2 = x1 * y1
  z0 = x0 * y0
  z1 = (x1 + x0) * (y1 + y0) - z2 - z0
  x * y = z2 * 10^(2m) + z1 * 10^m + z0

Esta implementacion trabaja con long. El signo se maneja aparte y la recursión opera sobre los valores absolutos. Los resultados deben caber en un long (no hay aritmetica de precision arbitraria).

/**
 * e10: multiplicacion de enteros con la idea de Karatsuba.
 *
 * <p>La multiplicacion escolar de dos numeros de {@code n} digitos hace
 * O(n^2) productos de un digito. Karatsuba parte cada numero en dos mitades y,
 * mediante un truco algebraico, resuelve el problema con <b>tres</b>
 * multiplicaciones de la mitad del tamano en vez de cuatro, bajando la
 * complejidad a O(n^1.585).</p>
 *
 * <p>Si {@code x = x1 * 10^m + x0} e {@code y = y1 * 10^m + y0}, entonces:</p>
 * <pre>
 *   z2 = x1 * y1
 *   z0 = x0 * y0
 *   z1 = (x1 + x0) * (y1 + y0) - z2 - z0
 *   x * y = z2 * 10^(2m) + z1 * 10^m + z0
 * </pre>
 *
 * <p>Esta implementacion trabaja con {@code long}. El signo se maneja aparte y
 * la recursion opera sobre los valores absolutos. Los resultados deben caber en
 * un {@code long} (no hay aritmetica de precision arbitraria).</p>
 */
public final class KaratsubaLong {

    private KaratsubaLong() {
    }

    /**
     * Multiplica {@code x} por {@code y} con el metodo de Karatsuba.
     *
     * @param x primer factor (puede ser negativo)
     * @param y segundo factor (puede ser negativo)
     * @return el producto {@code x * y}
     */
    public static long multiplicar(long x, long y) {
        // El signo se resuelve aparte; recurrimos sobre los valores absolutos.
        boolean negativo = (x < 0) ^ (y < 0);
        long producto = karatsuba(Math.abs(x), Math.abs(y));
        return negativo ? -producto : producto;
    }

    /** Karatsuba sobre valores no negativos. */
    private static long karatsuba(long x, long y) {
        // Caso base: alguno cabe en un digito decimal => producto directo.
        if (x < 10 || y < 10) {
            return x * y;
        }
        // m = mitad de la cantidad de digitos del mayor de los dos.
        int digitos = Math.max(cantidadDigitos(x), cantidadDigitos(y));
        int m = digitos / 2;
        long potencia = potenciaDe10(m); // 10^m

        long x1 = x / potencia;
        long x0 = x % potencia;
        long y1 = y / potencia;
        long y0 = y % potencia;

        long z2 = karatsuba(x1, y1);
        long z0 = karatsuba(x0, y0);
        long z1 = karatsuba(x1 + x0, y1 + y0) - z2 - z0;

        return z2 * potenciaDe10(2 * m) + z1 * potencia + z0;
    }

    private static int cantidadDigitos(long n) {
        if (n == 0) {
            return 1;
        }
        int d = 0;
        while (n > 0) {
            d++;
            n /= 10;
        }
        return d;
    }

    private static long potenciaDe10(int exp) {
        long r = 1L;
        for (int i = 0; i < exp; i++) {
            r *= 10L;
        }
        return r;
    }

    public static void main(String[] args) {
        System.out.println("1234 * 5678 = " + multiplicar(1234, 5678));
        System.out.println("-12 * 34    = " + multiplicar(-12, 34));
        System.out.println("99999 * 99999 = " + multiplicar(99999, 99999));
    }
}

Counting sort

Ordenamiento por conteo (counting sort).

Pista

Es un ordenamiento no comparativo: no compara elementos entre si, sino que cuenta cuantas veces aparece cada valor y luego reconstruye el arreglo en orden. Funciona para enteros no negativos en el rango [0, maximo].

Complejidad temporal: O(n + k) donde k = maximo. Complejidad espacial: O(k).

import java.util.Arrays;

/**
 * e01: ordenamiento por conteo (counting sort).
 *
 * <p>Es un ordenamiento <b>no comparativo</b>: no compara elementos entre si,
 * sino que cuenta cuantas veces aparece cada valor y luego reconstruye el
 * arreglo en orden. Funciona para enteros no negativos en el rango
 * {@code [0, maximo]}.</p>
 *
 * <p>Complejidad temporal: {@code O(n + k)} donde {@code k = maximo}.
 * Complejidad espacial: {@code O(k)}.</p>
 */
public final class CountingSort {

    private CountingSort() {
    }

    /**
     * Ordena un arreglo de enteros no negativos usando conteo.
     *
     * @param a       arreglo de entrada (no se modifica)
     * @param maximo  valor maximo posible presente en {@code a} (>= 0)
     * @return un arreglo nuevo con los mismos elementos ordenados de menor a mayor
     * @throws IllegalArgumentException si {@code maximo} es negativo o si hay
     *                                  algun valor fuera del rango {@code [0, maximo]}
     */
    public static int[] ordenar(int[] a, int maximo) {
        if (maximo < 0) {
            throw new IllegalArgumentException("maximo no puede ser negativo: " + maximo);
        }
        // conteos[v] = cantidad de veces que aparece el valor v
        int[] conteos = new int[maximo + 1];
        for (int valor : a) {
            if (valor < 0 || valor > maximo) {
                throw new IllegalArgumentException(
                        "valor fuera del rango [0, " + maximo + "]: " + valor);
            }
            conteos[valor]++;
        }
        // Reconstruimos el arreglo ordenado recorriendo los valores en orden.
        int[] resultado = new int[a.length];
        int indice = 0;
        for (int valor = 0; valor <= maximo; valor++) {
            for (int i = 0; i < conteos[valor]; i++) {
                resultado[indice++] = valor;
            }
        }
        return resultado;
    }

    public static void main(String[] args) {
        int[] datos = {4, 2, 2, 8, 3, 3, 1, 0, 7};
        System.out.println("original:  " + Arrays.toString(datos));
        System.out.println("ordenado:  " + Arrays.toString(ordenar(datos, 8)));
    }
}

Radix sort

Ordenamiento por radix (LSD, del dígito menos significativo al mas significativo) para enteros no negativos en base 10.

Pista

Es un ordenamiento no comparativo: ordena repetidamente por cada dígito, de derecha a izquierda, usando un conteo estable en cada paso. La estabilidad es la clave: preserva el orden relativo logrado por los dígitos anteriores.

Complejidad temporal: O(d * (n + 10)) donde d es la cantidad de dígitos del máximo.

import java.util.Arrays;

/**
 * e02: ordenamiento por radix (LSD, del digito menos significativo al mas
 * significativo) para enteros no negativos en base 10.
 *
 * <p>Es un ordenamiento <b>no comparativo</b>: ordena repetidamente por cada
 * digito, de derecha a izquierda, usando un conteo <b>estable</b> en cada paso.
 * La estabilidad es la clave: preserva el orden relativo logrado por los
 * digitos anteriores.</p>
 *
 * <p>Complejidad temporal: {@code O(d * (n + 10))} donde {@code d} es la
 * cantidad de digitos del maximo.</p>
 */
public final class RadixSort {

    private RadixSort() {
    }

    /**
     * Ordena un arreglo de enteros no negativos.
     *
     * @param a arreglo de entrada (no se modifica)
     * @return un arreglo nuevo ordenado de menor a mayor
     * @throws IllegalArgumentException si algun valor es negativo
     */
    public static int[] ordenar(int[] a) {
        for (int valor : a) {
            if (valor < 0) {
                throw new IllegalArgumentException("radix LSD solo admite no negativos: " + valor);
            }
        }
        if (a.length == 0) {
            return new int[0];
        }
        int maximo = Arrays.stream(a).max().getAsInt();
        int[] actual = a.clone();
        // Recorremos cada posicion decimal mientras exista un digito significativo.
        for (int exp = 1; maximo / exp > 0; exp *= 10) {
            actual = ordenarPorDigito(actual, exp);
        }
        return actual;
    }

    /**
     * Counting sort estable usando el digito de {@code a} en la posicion
     * indicada por {@code exp} (1 = unidades, 10 = decenas, ...).
     */
    private static int[] ordenarPorDigito(int[] a, int exp) {
        int[] conteos = new int[10];
        for (int valor : a) {
            int digito = (valor / exp) % 10;
            conteos[digito]++;
        }
        // Suma acumulada: conteos[d] pasa a ser la posicion final (exclusiva)
        // del ultimo elemento con digito d.
        for (int d = 1; d < 10; d++) {
            conteos[d] += conteos[d - 1];
        }
        int[] resultado = new int[a.length];
        // Recorremos de derecha a izquierda para mantener la estabilidad.
        for (int i = a.length - 1; i >= 0; i--) {
            int digito = (a[i] / exp) % 10;
            resultado[--conteos[digito]] = a[i];
        }
        return resultado;
    }

    public static void main(String[] args) {
        int[] datos = {170, 45, 75, 90, 802, 24, 2, 66};
        System.out.println("original:  " + Arrays.toString(datos));
        System.out.println("ordenado:  " + Arrays.toString(ordenar(datos)));
    }
}

Bucket sort

Ordenamiento por cubetas (bucket sort) para números reales uniformemente distribuidos en el intervalo [0, 1).

Pista

Idea: se reparten los n valores en n cubetas segun su magnitud (la cubeta de x es floor(n * x)). Cada cubeta se ordena por separado y luego se concatenan en orden. Si los datos estan bien distribuidos, el costo promedio es O(n).

import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.List;

/**
 * e03: ordenamiento por cubetas (bucket sort) para numeros reales uniformemente
 * distribuidos en el intervalo {@code [0, 1)}.
 *
 * <p>Idea: se reparten los {@code n} valores en {@code n} cubetas segun su
 * magnitud (la cubeta de {@code x} es {@code floor(n * x)}). Cada cubeta se
 * ordena por separado y luego se concatenan en orden. Si los datos estan
 * bien distribuidos, el costo promedio es {@code O(n)}.</p>
 */
public final class BucketSort {

    private BucketSort() {
    }

    /**
     * Ordena un arreglo de reales en {@code [0, 1)}.
     *
     * @param a arreglo de entrada (no se modifica)
     * @return un arreglo nuevo ordenado de menor a mayor
     * @throws IllegalArgumentException si algun valor no esta en {@code [0, 1)}
     */
    public static double[] ordenar(double[] a) {
        int n = a.length;
        if (n == 0) {
            return new double[0];
        }
        // Una cubeta (lista) por cada franja del intervalo.
        List<List<Double>> cubetas = new ArrayList<>(n);
        for (int i = 0; i < n; i++) {
            cubetas.add(new ArrayList<>());
        }
        for (double valor : a) {
            if (valor < 0.0 || valor >= 1.0) {
                throw new IllegalArgumentException("valor fuera de [0, 1): " + valor);
            }
            int indice = (int) (n * valor);
            cubetas.get(indice).add(valor);
        }
        // Ordenamos cada cubeta y concatenamos en orden.
        double[] resultado = new double[n];
        int pos = 0;
        for (List<Double> cubeta : cubetas) {
            Collections.sort(cubeta);
            for (double valor : cubeta) {
                resultado[pos++] = valor;
            }
        }
        return resultado;
    }

    public static void main(String[] args) {
        double[] datos = {0.42, 0.11, 0.99, 0.01, 0.5, 0.5, 0.73};
        System.out.println("original:  " + Arrays.toString(datos));
        System.out.println("ordenado:  " + Arrays.toString(ordenar(datos)));
    }
}

Subconjuntos (conjunto potencia)

Generacion del conjunto potencia (power set) de forma recursiva.

Pista

El conjunto potencia de una lista de n elementos tiene 2^n subconjuntos. Estrategia de división y conquista: para el primer elemento hay dos decisiones (incluirlo o no); el resto de los subconjuntos se obtiene recursivamente sobre la cola de la lista.

import java.util.ArrayList;
import java.util.List;

/**
 * e04: generacion del conjunto potencia (power set) de forma recursiva.
 *
 * <p>El conjunto potencia de una lista de {@code n} elementos tiene
 * {@code 2^n} subconjuntos. Estrategia de division y conquista: para el primer
 * elemento hay dos decisiones (incluirlo o no); el resto de los subconjuntos se
 * obtiene recursivamente sobre la cola de la lista.</p>
 */
public final class Subconjuntos {

    private Subconjuntos() {
    }

    /**
     * Devuelve todos los subconjuntos de {@code l} (incluye el vacio y el total).
     *
     * @param l lista de elementos
     * @return lista con los {@code 2^n} subconjuntos
     */
    public static List<List<Integer>> subconjuntos(List<Integer> l) {
        List<List<Integer>> resultado = new ArrayList<>();
        generar(l, 0, new ArrayList<>(), resultado);
        return resultado;
    }

    /**
     * Recorre las decisiones incluir/excluir para cada elemento a partir de
     * {@code indice}, acumulando en {@code parcial}.
     */
    private static void generar(List<Integer> l, int indice,
                                List<Integer> parcial, List<List<Integer>> resultado) {
        if (indice == l.size()) {
            resultado.add(new ArrayList<>(parcial)); // caso base: copia del subconjunto actual
            return;
        }
        // Decision 1: NO incluir el elemento en la posicion indice.
        generar(l, indice + 1, parcial, resultado);
        // Decision 2: SI incluirlo.
        parcial.add(l.get(indice));
        generar(l, indice + 1, parcial, resultado);
        parcial.remove(parcial.size() - 1); // deshacemos para backtracking
    }

    public static void main(String[] args) {
        List<Integer> datos = List.of(1, 2, 3);
        List<List<Integer>> todos = subconjuntos(datos);
        System.out.println("cantidad = " + todos.size() + " (esperado 2^3 = 8)");
        todos.forEach(System.out::println);
    }
}

Permutaciones

Generacion de todas las permutaciones de una lista de forma recursiva.

Pista

Una lista de n elementos tiene n! permutaciones. Estrategia de backtracking: en cada paso se elige un elemento aún no usado para la siguiente posición, se recurre, y luego se deshace la elección.

import java.util.ArrayList;
import java.util.List;

/**
 * e05: generacion de todas las permutaciones de una lista de forma recursiva.
 *
 * <p>Una lista de {@code n} elementos tiene {@code n!} permutaciones. Estrategia
 * de backtracking: en cada paso se elige un elemento aun no usado para la
 * siguiente posicion, se recurre, y luego se deshace la eleccion.</p>
 */
public final class Permutaciones {

    private Permutaciones() {
    }

    /**
     * Devuelve todas las permutaciones de {@code l}.
     *
     * @param l lista de elementos (se asumen distintos)
     * @return lista con las {@code n!} permutaciones
     */
    public static List<List<Integer>> permutaciones(List<Integer> l) {
        List<List<Integer>> resultado = new ArrayList<>();
        boolean[] usado = new boolean[l.size()];
        generar(l, usado, new ArrayList<>(), resultado);
        return resultado;
    }

    /**
     * Construye permutaciones eligiendo, en cada posicion, un elemento libre.
     */
    private static void generar(List<Integer> l, boolean[] usado,
                                List<Integer> parcial, List<List<Integer>> resultado) {
        if (parcial.size() == l.size()) {
            resultado.add(new ArrayList<>(parcial)); // caso base: permutacion completa
            return;
        }
        for (int i = 0; i < l.size(); i++) {
            if (usado[i]) {
                continue; // ya lo pusimos en una posicion anterior
            }
            usado[i] = true;
            parcial.add(l.get(i));
            generar(l, usado, parcial, resultado);
            parcial.remove(parcial.size() - 1); // deshacemos (backtracking)
            usado[i] = false;
        }
    }

    public static void main(String[] args) {
        List<Integer> datos = List.of(1, 2, 3);
        List<List<Integer>> todas = permutaciones(datos);
        System.out.println("cantidad = " + todas.size() + " (esperado 3! = 6)");
        todas.forEach(System.out::println);
    }
}

Combinaciones

Generacion de todas las combinaciones de k elementos tomados de una lista, mediante backtracking.

Pista

La cantidad de combinaciones es el número combinatorio C(n, k). A diferencia de las permutaciones, el orden no importa: para evitar repetir combinaciones, siempre avanzamos hacia adelante en la lista (nunca miramos indices anteriores al ultimo elegido).

import java.util.ArrayList;
import java.util.List;

/**
 * e06: generacion de todas las combinaciones de {@code k} elementos tomados de
 * una lista, mediante backtracking.
 *
 * <p>La cantidad de combinaciones es el numero combinatorio {@code C(n, k)}.
 * A diferencia de las permutaciones, el orden no importa: para evitar repetir
 * combinaciones, siempre avanzamos hacia adelante en la lista (nunca miramos
 * indices anteriores al ultimo elegido).</p>
 */
public final class Combinaciones {

    private Combinaciones() {
    }

    /**
     * Devuelve todas las combinaciones de {@code k} elementos de {@code l}.
     *
     * @param l lista de elementos
     * @param k cantidad de elementos por combinacion (0 &lt;= k &lt;= n)
     * @return lista con las {@code C(n, k)} combinaciones
     * @throws IllegalArgumentException si {@code k} esta fuera de {@code [0, n]}
     */
    public static List<List<Integer>> combinaciones(List<Integer> l, int k) {
        if (k < 0 || k > l.size()) {
            throw new IllegalArgumentException("k fuera de rango [0, " + l.size() + "]: " + k);
        }
        List<List<Integer>> resultado = new ArrayList<>();
        generar(l, k, 0, new ArrayList<>(), resultado);
        return resultado;
    }

    /**
     * Elige elementos desde {@code inicio} hacia adelante hasta completar
     * {@code k} en {@code parcial}.
     */
    private static void generar(List<Integer> l, int k, int inicio,
                                List<Integer> parcial, List<List<Integer>> resultado) {
        if (parcial.size() == k) {
            resultado.add(new ArrayList<>(parcial)); // caso base: combinacion completa
            return;
        }
        // Poda: si ni tomando todos los restantes llegamos a k, cortamos.
        for (int i = inicio; i <= l.size() - (k - parcial.size()); i++) {
            parcial.add(l.get(i));
            generar(l, k, i + 1, parcial, resultado); // i + 1: nunca miramos atras
            parcial.remove(parcial.size() - 1); // backtracking
        }
    }

    public static void main(String[] args) {
        List<Integer> datos = List.of(1, 2, 3, 4);
        List<List<Integer>> todas = combinaciones(datos, 2);
        System.out.println("cantidad = " + todas.size() + " (esperado C(4,2) = 6)");
        todas.forEach(System.out::println);
    }
}

Laberinto

Búsqueda de un camino en un laberinto mediante backtracking recursivo.

Pista

El laberinto es una grilla libre[fila][columna]: true significa que la celda es transitable. Partiendo de (0,0) se busca llegar a (n-1, m-1) moviendose por celdas libres en las 4 direcciones (arriba, abajo, izquierda, derecha), sin repetir celdas ya visitadas.

/**
 * e07: busqueda de un camino en un laberinto mediante backtracking recursivo.
 *
 * <p>El laberinto es una grilla {@code libre[fila][columna]}: {@code true}
 * significa que la celda es transitable. Partiendo de {@code (0,0)} se busca
 * llegar a {@code (n-1, m-1)} moviendose por celdas libres en las 4 direcciones
 * (arriba, abajo, izquierda, derecha), sin repetir celdas ya visitadas.</p>
 */
public final class Laberinto {

    private Laberinto() {
    }

    /**
     * Indica si existe un camino desde la esquina superior izquierda hasta la
     * inferior derecha.
     *
     * @param libre grilla rectangular de celdas transitables
     * @return {@code true} si hay camino; {@code false} en caso contrario
     * @throws IllegalArgumentException si la grilla es nula o esta vacia
     */
    public static boolean hayCamino(boolean[][] libre) {
        if (libre == null || libre.length == 0 || libre[0].length == 0) {
            throw new IllegalArgumentException("el laberinto no puede ser vacio");
        }
        int filas = libre.length;
        int columnas = libre[0].length;
        // Si la salida o la entrada estan bloqueadas, no hay camino posible.
        if (!libre[0][0] || !libre[filas - 1][columnas - 1]) {
            return false;
        }
        boolean[][] visitada = new boolean[filas][columnas];
        return explorar(libre, visitada, 0, 0);
    }

    /**
     * Intenta avanzar recursivamente desde {@code (fila, columna)} hacia el
     * destino, marcando y desmarcando celdas visitadas (backtracking).
     */
    private static boolean explorar(boolean[][] libre, boolean[][] visitada,
                                    int fila, int columna) {
        int filas = libre.length;
        int columnas = libre[0].length;
        // Fuera de la grilla, pared o ya visitada: callejon sin salida.
        if (fila < 0 || fila >= filas || columna < 0 || columna >= columnas) {
            return false;
        }
        if (!libre[fila][columna] || visitada[fila][columna]) {
            return false;
        }
        // Llegamos al destino.
        if (fila == filas - 1 && columna == columnas - 1) {
            return true;
        }
        visitada[fila][columna] = true;
        // Probamos las 4 direcciones.
        boolean encontrado = explorar(libre, visitada, fila - 1, columna)
                || explorar(libre, visitada, fila + 1, columna)
                || explorar(libre, visitada, fila, columna - 1)
                || explorar(libre, visitada, fila, columna + 1);
        if (!encontrado) {
            visitada[fila][columna] = false; // deshacemos para permitir otros caminos
        }
        return encontrado;
    }

    public static void main(String[] args) {
        boolean[][] conSalida = {
                {true, true, false},
                {false, true, false},
                {false, true, true}
        };
        boolean[][] sinSalida = {
                {true, false},
                {false, true}
        };
        System.out.println("conSalida -> " + hayCamino(conSalida));
        System.out.println("sinSalida -> " + hayCamino(sinSalida));
    }
}

Quickselect

Selección del k-esimo menor elemento con el algoritmo Quickselect.

Pista

Quickselect reutiliza la partición de Quicksort, pero en lugar de ordenar ambas mitades solo recurre sobre la que contiene la posición buscada. Esto da un costo promedio O(n) (peor caso O(n^2)), mejor que ordenar todo el arreglo en O(n log n).

import java.util.Arrays;

/**
 * e08: seleccion del k-esimo menor elemento con el algoritmo Quickselect.
 *
 * <p>Quickselect reutiliza la particion de Quicksort, pero en lugar de ordenar
 * ambas mitades solo recurre sobre la que contiene la posicion buscada. Esto da
 * un costo promedio {@code O(n)} (peor caso {@code O(n^2)}), mejor que ordenar
 * todo el arreglo en {@code O(n log n)}.</p>
 */
public final class QuickSelect {

    private QuickSelect() {
    }

    /**
     * Devuelve el {@code k}-esimo menor elemento (k = 1 es el minimo).
     *
     * @param a arreglo de entrada (no se modifica: se trabaja sobre una copia)
     * @param k posicion buscada en orden creciente, entre {@code 1} y {@code n}
     * @return el valor que quedaria en la posicion {@code k-1} si se ordenara
     * @throws IllegalArgumentException si {@code k} esta fuera de {@code [1, n]}
     */
    public static int kEsimoMenor(int[] a, int k) {
        if (k < 1 || k > a.length) {
            throw new IllegalArgumentException("k fuera de rango [1, " + a.length + "]: " + k);
        }
        int[] copia = a.clone();
        return seleccionar(copia, 0, copia.length - 1, k - 1); // pasamos a indice base 0
    }

    /**
     * Busca el elemento cuyo indice ordenado es {@code objetivo} dentro de
     * {@code [izq, der]}.
     */
    private static int seleccionar(int[] a, int izq, int der, int objetivo) {
        if (izq == der) {
            return a[izq]; // caso base: un solo elemento
        }
        int posPivote = particionar(a, izq, der);
        if (objetivo == posPivote) {
            return a[posPivote];
        } else if (objetivo < posPivote) {
            return seleccionar(a, izq, posPivote - 1, objetivo);
        } else {
            return seleccionar(a, posPivote + 1, der, objetivo);
        }
    }

    /**
     * Particion estilo Lomuto: usa {@code a[der]} como pivote y devuelve su
     * posicion final. A la izquierda quedan los menores o iguales; a la derecha
     * los mayores.
     */
    private static int particionar(int[] a, int izq, int der) {
        int pivote = a[der];
        int i = izq;
        for (int j = izq; j < der; j++) {
            if (a[j] <= pivote) {
                intercambiar(a, i, j);
                i++;
            }
        }
        intercambiar(a, i, der);
        return i;
    }

    private static void intercambiar(int[] a, int i, int j) {
        int tmp = a[i];
        a[i] = a[j];
        a[j] = tmp;
    }

    public static void main(String[] args) {
        int[] datos = {7, 2, 9, 4, 1, 8, 3};
        for (int k = 1; k <= datos.length; k++) {
            System.out.println(k + "-esimo menor = " + kEsimoMenor(datos, k));
        }
        System.out.println("orden real: " + Arrays.toString(datos.clone()));
    }
}

Mergesort sobre lista enlazada

Ordenamiento por mezcla (Mergesort) sobre una lista simplemente enlazada de enteros.

Pista

Mergesort es ideal para listas enlazadas: no necesita acceso por índice y la mezcla se hace reenlazando nodos, sin copiar arreglos. La lista se parte en dos mitades con la técnica de los dos punteros (uno lento que avanza de a un nodo y uno rápido que avanza de a dos): cuando el rápido llega al final, el lento quedo en el medio.

Complejidad temporal: O(n log n).

// MergesortLista.java
/**
 * e09: ordenamiento por mezcla (Mergesort) sobre una lista simplemente
 * enlazada de enteros.
 *
 * <p>Mergesort es ideal para listas enlazadas: no necesita acceso por indice y
 * la mezcla se hace reenlazando nodos, sin copiar arreglos. La lista se parte en
 * dos mitades con la tecnica de los dos punteros (uno lento que avanza de a un
 * nodo y uno rapido que avanza de a dos): cuando el rapido llega al final, el
 * lento quedo en el medio.</p>
 *
 * <p>Complejidad temporal: {@code O(n log n)}.</p>
 */
public final class MergesortLista {

    private MergesortLista() {
    }

    /**
     * Construye una lista enlazada a partir de un arreglo (util para pruebas y demo).
     *
     * @param valores valores en orden
     * @return la cabeza de la lista, o {@code null} si el arreglo esta vacio
     */
    public static Nodo desdeArreglo(int[] valores) {
        Nodo cabeza = null;
        for (int i = valores.length - 1; i >= 0; i--) {
            Nodo nuevo = new Nodo(valores[i]);
            nuevo.siguiente = cabeza;
            cabeza = nuevo;
        }
        return cabeza;
    }

    /**
     * Vuelca la lista a un arreglo (util para pruebas y demo).
     *
     * @param cabeza cabeza de la lista
     * @return arreglo con los datos en el orden de la lista
     */
    public static int[] aArreglo(Nodo cabeza) {
        int largo = 0;
        for (Nodo n = cabeza; n != null; n = n.siguiente) {
            largo++;
        }
        int[] resultado = new int[largo];
        int i = 0;
        for (Nodo n = cabeza; n != null; n = n.siguiente) {
            resultado[i++] = n.dato;
        }
        return resultado;
    }

    /**
     * Ordena la lista de menor a mayor y devuelve la nueva cabeza.
     *
     * @param cabeza cabeza de la lista (puede ser {@code null})
     * @return cabeza de la lista ordenada
     */
    public static Nodo ordenar(Nodo cabeza) {
        // Caso base: lista vacia o de un solo nodo, ya esta ordenada.
        if (cabeza == null || cabeza.siguiente == null) {
            return cabeza;
        }
        // Dividir: partimos en dos mitades.
        Nodo medio = partir(cabeza);
        Nodo segundaMitad = medio.siguiente;
        medio.siguiente = null; // cortamos el enlace entre mitades

        // Conquistar: ordenamos cada mitad recursivamente.
        Nodo izquierda = ordenar(cabeza);
        Nodo derecha = ordenar(segundaMitad);

        // Combinar: mezclamos las dos mitades ordenadas.
        return mezclar(izquierda, derecha);
    }

    /**
     * Devuelve el nodo medio (final de la primera mitad) usando dos punteros:
     * el lento avanza de a uno, el rapido de a dos.
     */
    private static Nodo partir(Nodo cabeza) {
        Nodo lento = cabeza;
        Nodo rapido = cabeza.siguiente;
        while (rapido != null && rapido.siguiente != null) {
            lento = lento.siguiente;
            rapido = rapido.siguiente.siguiente;
        }
        return lento;
    }

    /**
     * Mezcla dos listas ordenadas reenlazando nodos (sin crear nodos nuevos).
     */
    private static Nodo mezclar(Nodo a, Nodo b) {
        Nodo centinela = new Nodo(0); // nodo ficticio para simplificar el enlace
        Nodo cola = centinela;
        while (a != null && b != null) {
            if (a.dato <= b.dato) {
                cola.siguiente = a;
                a = a.siguiente;
            } else {
                cola.siguiente = b;
                b = b.siguiente;
            }
            cola = cola.siguiente;
        }
        cola.siguiente = (a != null) ? a : b; // enganchamos lo que reste
        return centinela.siguiente;
    }

    public static void main(String[] args) {
        Nodo lista = desdeArreglo(new int[]{5, 2, 9, 1, 5, 6, 3});
        Nodo ordenada = ordenar(lista);
        System.out.print("ordenada: ");
        for (Nodo n = ordenada; n != null; n = n.siguiente) {
            System.out.print(n.dato + " ");
        }
        System.out.println();
    }
}

Comparativa de ordenamientos

Comparativa de algoritmos de ordenamiento.

Pista

Aplica cuatro algoritmos distintos (Mergesort y Quicksort comparativos; Counting y Radix no comparativos) al mismo arreglo y verifica que los cuatro produzcan exactamente el mismo resultado que java.util.Arrays#sort. Es una forma de testeo cruzado: si todos coinciden, es muy probable que las cuatro implementaciones sean correctas.

Todos los algoritmos estan reimplementados dentro de este paquete para que el ejercicio sea autocontenido. Como Counting y Radix trabajan sobre enteros no negativos, la comparativa exige entradas no negativas.

import java.util.Arrays;

/**
 * e10: comparativa de algoritmos de ordenamiento.
 *
 * <p>Aplica cuatro algoritmos distintos (Mergesort y Quicksort comparativos;
 * Counting y Radix no comparativos) al mismo arreglo y verifica que los cuatro
 * produzcan exactamente el mismo resultado que {@link java.util.Arrays#sort}.
 * Es una forma de testeo cruzado: si todos coinciden, es muy probable que las
 * cuatro implementaciones sean correctas.</p>
 *
 * <p>Todos los algoritmos estan reimplementados dentro de este paquete para que
 * el ejercicio sea autocontenido. Como Counting y Radix trabajan sobre enteros
 * no negativos, la comparativa exige entradas no negativas.</p>
 */
public final class ComparativaOrdenamientos {

    private ComparativaOrdenamientos() {
    }

    /**
     * Ordena {@code a} con los cuatro algoritmos y con {@code Arrays.sort} y
     * verifica que todos den el mismo resultado.
     *
     * @param a arreglo de enteros no negativos (no se modifica)
     * @return {@code true} si los cuatro algoritmos coinciden con {@code Arrays.sort}
     * @throws IllegalArgumentException si algun valor es negativo
     */
    public static boolean todosCoinciden(int[] a) {
        for (int valor : a) {
            if (valor < 0) {
                throw new IllegalArgumentException(
                        "la comparativa exige valores no negativos: " + valor);
            }
        }
        int[] referencia = a.clone();
        Arrays.sort(referencia);

        return Arrays.equals(referencia, mergesort(a))
                && Arrays.equals(referencia, quicksort(a))
                && Arrays.equals(referencia, counting(a))
                && Arrays.equals(referencia, radix(a));
    }

    // ---------------------------------------------------------------------
    // Mergesort
    // ---------------------------------------------------------------------

    private static int[] mergesort(int[] a) {
        int[] copia = a.clone();
        if (copia.length > 1) {
            mergesortRec(copia, 0, copia.length - 1, new int[copia.length]);
        }
        return copia;
    }

    private static void mergesortRec(int[] a, int izq, int der, int[] aux) {
        if (izq >= der) {
            return;
        }
        int medio = (izq + der) / 2;
        mergesortRec(a, izq, medio, aux);
        mergesortRec(a, medio + 1, der, aux);
        mezclar(a, izq, medio, der, aux);
    }

    private static void mezclar(int[] a, int izq, int medio, int der, int[] aux) {
        for (int i = izq; i <= der; i++) {
            aux[i] = a[i];
        }
        int i = izq;
        int j = medio + 1;
        for (int k = izq; k <= der; k++) {
            if (i > medio) {
                a[k] = aux[j++];
            } else if (j > der) {
                a[k] = aux[i++];
            } else if (aux[i] <= aux[j]) {
                a[k] = aux[i++];
            } else {
                a[k] = aux[j++];
            }
        }
    }

    // ---------------------------------------------------------------------
    // Quicksort
    // ---------------------------------------------------------------------

    private static int[] quicksort(int[] a) {
        int[] copia = a.clone();
        quicksortRec(copia, 0, copia.length - 1);
        return copia;
    }

    private static void quicksortRec(int[] a, int izq, int der) {
        if (izq >= der) {
            return;
        }
        int posPivote = particionar(a, izq, der);
        quicksortRec(a, izq, posPivote - 1);
        quicksortRec(a, posPivote + 1, der);
    }

    private static int particionar(int[] a, int izq, int der) {
        int pivote = a[der];
        int i = izq;
        for (int j = izq; j < der; j++) {
            if (a[j] <= pivote) {
                intercambiar(a, i, j);
                i++;
            }
        }
        intercambiar(a, i, der);
        return i;
    }

    private static void intercambiar(int[] a, int i, int j) {
        int tmp = a[i];
        a[i] = a[j];
        a[j] = tmp;
    }

    // ---------------------------------------------------------------------
    // Counting sort
    // ---------------------------------------------------------------------

    private static int[] counting(int[] a) {
        if (a.length == 0) {
            return new int[0];
        }
        int maximo = Arrays.stream(a).max().getAsInt();
        int[] conteos = new int[maximo + 1];
        for (int valor : a) {
            conteos[valor]++;
        }
        int[] resultado = new int[a.length];
        int indice = 0;
        for (int valor = 0; valor <= maximo; valor++) {
            for (int i = 0; i < conteos[valor]; i++) {
                resultado[indice++] = valor;
            }
        }
        return resultado;
    }

    // ---------------------------------------------------------------------
    // Radix sort (LSD, base 10)
    // ---------------------------------------------------------------------

    private static int[] radix(int[] a) {
        if (a.length == 0) {
            return new int[0];
        }
        int maximo = Arrays.stream(a).max().getAsInt();
        int[] actual = a.clone();
        for (int exp = 1; maximo / exp > 0; exp *= 10) {
            actual = radixPorDigito(actual, exp);
        }
        return actual;
    }

    private static int[] radixPorDigito(int[] a, int exp) {
        int[] conteos = new int[10];
        for (int valor : a) {
            conteos[(valor / exp) % 10]++;
        }
        for (int d = 1; d < 10; d++) {
            conteos[d] += conteos[d - 1];
        }
        int[] resultado = new int[a.length];
        for (int i = a.length - 1; i >= 0; i--) {
            int digito = (a[i] / exp) % 10;
            resultado[--conteos[digito]] = a[i];
        }
        return resultado;
    }

    public static void main(String[] args) {
        int[][] casos = {
                {5, 2, 9, 1, 5, 6, 3},
                {170, 45, 75, 90, 802, 24, 2, 66},
                {},
                {7}
        };
        for (int[] caso : casos) {
            System.out.println(Arrays.toString(caso) + " -> coinciden: " + todosCoinciden(caso));
        }
    }
}
