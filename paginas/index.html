❓ Cómo funcionan los ejercicios y los tests

1 · Cada ejercicio vive en DOS lugares

El proyecto separa tu solución de la prueba que la verifica, en dos árboles paralelos con el mismo nombre de paquete:

teoria/cb100/app/src/
├── main/java/…/guia/i01_intro/i02_facil/e02/
│   └── Operaciones.java        ← LA SOLUCIÓN (los métodos que resolvés)
└── test/java/…/guia/i01_intro/i02_facil/e02/
    └── OperacionesTest.java     ← EL TEST (comprueba que esté bien)

La ruta es idéntica salvo main vs test, y el nombre es Operaciones → OperacionesTest. Esa convención es la que hace que el test "vea" tu clase y pueda llamarla.

2 · El archivo de solución: métodos vs main

public class Operaciones {
    public static int suma(int a, int b) { return a + b; }   ← MÉTODO: hace el trabajo
    public static int resta(int a, int b) { return a - b; }

    public static void main(String[] args) {                 ← main: demo manual
        System.out.println("suma(2, 3) = " + suma(2, 3));       imprime, NO verifica
    }
}

Los métodos (suma, resta…) son lo que resolvés: reciben datos y devuelven un resultado. El main es opcional: si le das ▶ en IntelliJ, solo imprime cosas para que las mires vos.

3 · El test: verifica los métodos solo

class OperacionesTest {
    @Test                                          ← cada @Test es una comprobación
    void suma() {
        assertEquals(5, Operaciones.suma(2, 3));   ← espero 5, llamo a TU método
    }
    @Test
    void divisionPorCero() {
        assertThrows(ArithmeticException.class, () -> Operaciones.division(1, 0));
    }
}

La pieza clave es assertEquals(esperado, obtenido): el primer valor es el resultado correcto; el segundo es lo que devuelve tu método. Si coinciden → ✅ verde; si no → ❌ rojo, y te dice qué esperaba y qué obtuvo. assertThrows es la variante para "esto debe tirar un error".
